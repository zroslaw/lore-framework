# Migration to Version 37

## Summary

Relocates registered Codex per-agent shortcuts from the user's home directory
(`~/.codex/skills/lr-<agent-name>-agent/`) to the workspace-local location
(`<workspace>/.codex/skills/lr-<agent-name>-agent/`), which v37 makes the framework-managed
one. Codex loads skills from both roots, so this changes nothing about how a shortcut is
invoked — it changes who else can get it. A workspace-local shortcut is an ordinary file in
the workspace repo, published by `/lr:workspace-push` and received by a teammate's
`/lr:workspace-pull`; a home-directory one reaches nobody and is invisible to every workspace
command.

Codex only. On Claude Code and Cursor this migration inspects nothing and reports
`not applicable` — their shortcut locations are unchanged.

The migration relocates existing shortcuts only. It never creates a shortcut for an agent that
has none, and never touches a shortcut whose boot line names an agent directory outside the
booting repo: `~/.codex/skills` is user-global, and a same-named shortcut may belong to a
different workspace entirely.

## Scope

Apply this migration to the booting `<lore-agent-repo>`. Only shortcuts whose content names an agent
directory under `<lore-agent-repo>/agents/` are candidates.

`<workspace>` is the **workspace root**, not the session working directory — resolve it as
`migrations/44.md` § Scope specifies (the directory holding `lore-workspace.md`, else the parent of
`.worktrees/`, else the git toplevel of `<lore-agent-repo>`'s parent). A single `/lr:update` pass
runs this migration alongside 44, and two different meanings for one placeholder put the shortcut
locations and the relative paths written into them at odds.

Engine gate: apply only when the active engine profile is Codex
(`data.engine.name == "codex"` from `lr-core preflight`). On any other engine, report
`not applicable` and stop — do not infer the engine from what you believe you are running as
(`docs/engines/codex.md` § Detection blind spot; a Codex session off the native install needs
`--engine codex`).

## Steps

All steps are idempotent. Do not stamp `lore-repo.md` in this migration; the update process
stamps it only after every applicable migration succeeds.

### Step 1: Build the owned-agent map

Scan `<lore-agent-repo>/agents/` for directories containing `role.md`. For each, record:

- `<agent-name>` — the directory basename
- `<agent-dir>` — its absolute path
- `<agent-dir-rel>` — `<agent-dir>` relative to the workspace root, with a trailing `/`

A home shortcut names `<agent-dir>`; a workspace-local one has named `<agent-dir-rel>` since v44.
So match a home artifact on the absolute form, and write the relocated workspace copy with the
relative one (`register-repo.md` § Resolve the shortcut bootstrap).

### Step 2: Classify each owned agent's shortcuts

For every owned agent, inspect both locations:

- **home** — `~/.codex/skills/lr-<agent-name>-agent/SKILL.md`
- **workspace** — `<workspace>/.codex/skills/lr-<agent-name>-agent/SKILL.md`

Classify:

1. No home artifact → report `nothing to relocate` and continue. Do not create anything.
2. A home artifact whose boot line does **not** name this agent's `<agent-dir>` → report
   `foreign, left alone`. It belongs to another workspace, or to another agent of the same
   name (`docs/register-repo.md` § Collision rule). Never delete it.
3. A home artifact naming this agent's `<agent-dir>`, with no workspace artifact → `relocate`
   (Step 3).
4. A home artifact naming this agent's `<agent-dir>`, and a workspace artifact naming this same
   agent → `duplicate`: the workspace copy already exists, so the net effect is the removal
   of the home copy (Step 3 still refreshes the workspace copy to the current template). Codex
   lists both today, one of them unshareable.
5. A home artifact naming this agent's `<agent-dir>`, and a workspace artifact naming a
   **different** agent directory → report `collision, left alone` and do not delete the home copy.
   The workspace shortcut is owned by another agent directory; resolving that is the user's call.

Compare each artifact in the form its own location uses: the home copy names the absolute
`<agent-dir>`, while a workspace copy written at v44 or later names `<agent-dir-rel>`. Resolve the
workspace copy's target against the workspace root before deciding whether it is the same agent, or
a correctly-migrated shortcut reads as a collision and this migration silently stops relocating.

### Step 3: Relocate

For each `relocate` and `duplicate` agent:

1. **Write** `<workspace>/.codex/skills/lr-<agent-name>-agent/SKILL.md`
   using the current Codex template in `docs/register-repo.md` § Current shortcut templates,
   with the **exact Registered shortcut bootstrap** from `docs/engines/codex.md`, substituting
   the owned `<agent-name>` and `<agent-dir-rel>` — the destination is workspace-local, so it takes
   the relative form even though the home copy being replaced carries an absolute one
   (`docs/register-repo.md` § Resolve the shortcut bootstrap). The template's frontmatter also needs `<repo-name>`
   and `<agent-purpose>` — resolve them the way registration does (`docs/register-repo.md`
   § Resolve agent metadata), from the agent repo's directory name and the agent's `role.md`; do
   not carry them over from the home copy. Emit the bootstrap as one unwrapped line. Create
   the parent directories as needed. Registered shortcuts are framework-owned artifacts:
   customized generated content in the home copy is not carried over.

   This runs for `duplicate` too. The workspace copy that already exists may predate v37 — placed
   by hand, or arrived from a teammate on a dev build — and it is the copy that survives this
   migration, so it gets the same refresh every other path gets rather than being trusted on the
   strength of naming the right agent.
2. **Verify before deleting.** Confirm the workspace artifact now exists and its boot line names
   this agent's `<agent-dir-rel>` — the form Step 3.1 just wrote, not the absolute form the home
   copy used. If it does not, report a failure for this agent and **keep the home copy** — a
   deleted shortcut with no replacement is strictly worse than a duplicate.
3. **Delete** the home directory `~/.codex/skills/lr-<agent-name>-agent/`.

### Step 4: Maintain the workspace Agents section

After the last agent is processed, re-render the `## Agents` section of `<workspace>/AGENTS.md`
and ensure the `CLAUDE.md` import stub, exactly as `docs/register-repo.md` § Maintain the
workspace Agents section specifies. Membership has not changed, but the section is rendered from
the shortcuts on disk, and those just moved.

If `AGENTS.md` is absent or carries no `## Agents` heading, report that the workspace memory file
needs `/lr:workspace-init` and continue — the relocation itself has succeeded.

### Step 5: Report

Report each category separately:

- `relocated`
- `duplicate removed`
- `nothing to relocate`
- `foreign, left alone`
- `collision, left alone`
- `failed (home copy kept)`

State explicitly that no shortcut was created for an unregistered agent, that no foreign or
colliding artifact was deleted, and that the relocated shortcuts are now dirty in the workspace
repo — `/lr:workspace-push` publishes them.

## Write Paths

```
(none)
```

The migration writes only workspace-root and personal shortcut artifacts, which are outside the
boot-time repo-relative collision gate (`docs/conventions.md` § Known gap: workspace-root paths).
The ownership check in Step 2 and the verify-before-delete rule in Step 3 are the protection for
those paths.

## Dry-Run Mode

Perform the same inspection without writing or deleting. Report:

- `would relocate: <home-path> -> <workspace-path>`
- `would remove duplicate: <home-path>`
- `nothing to relocate: <agent-name>`
- `would leave foreign: <home-path>`
- `would leave collision: <home-path>`

Do not prompt in dry-run mode.
