# Migration to Version 33

## Summary

Refreshes existing registered per-agent shortcuts that still embed an absolute
`agent-boot.md` path. The replacement is the version-agnostic bootstrap introduced in
v32: it delegates to the active engine's installed boot skill and keeps only the agent
name and the agent directory — written in the form the target location requires, which since v44 is
workspace-relative everywhere except the user-global `~/.codex/skills/`.

The migration repairs existing shortcuts only. It never creates an optional shortcut or
replaces a shortcut that belongs to another agent directory. Registered shortcuts are
framework-owned artifacts: a shortcut that identifies the owned agent is regenerated even if
someone customized its boot path or other generated content.

## Clear Plugin Cache

This migration changes a plugin-cached migration procedure. Refresh the Lore plugin and
start a new session before running it, so the v33 migration is available:

1. **Claude Code:** `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback).
2. **Cursor:** run `bash /path/to/lore-framework/scripts/cursor-refresh-plugin`.
3. **Codex:** run `bash /path/to/lore-framework/scripts/codex-refresh-plugin`.

## Scope

Apply this migration to the booting `<lore-agent-repo>`. Only shortcuts whose content names an
agent directory under `<lore-agent-repo>/agents/` are candidates.

`<workspace>` is the **workspace root**, not the session working directory — resolve it as
`migrations/44.md` § Scope specifies (the directory holding `lore-workspace.md`, else the parent of
`.worktrees/`, else the git toplevel of `<lore-agent-repo>`'s parent). A single `/lr:update` pass
runs this migration alongside 44, and two different meanings for one placeholder put the shortcut
locations and the relative paths written into them at odds.

## Steps

All steps are idempotent. Do not stamp `lore-repo.md` in this migration; the update
process stamps it only after every applicable migration succeeds.

### Step 1: Build the owned-agent map

Scan `<lore-agent-repo>/agents/` for directories containing `role.md`. For each, record:

- `<agent-name>` — the directory basename
- `<agent-dir>` — its absolute path
- `<agent-dir-rel>` — `<agent-dir>` relative to the workspace root, with a trailing `/`, resolving
  both to real paths first (`migrations/44.md` § Step 1 states the macOS symlink trap in full)

Since v44 the bootstrap templates carry `<agent-dir-rel>`, not `<agent-dir>`: a workspace-local
shortcut names the agent directory relative to the workspace root, and only a `~/.codex/skills/`
shortcut keeps the absolute form. Use whichever the location being written calls for
(`register-repo.md` § Resolve the shortcut bootstrap). This applies to every comparison below as
well — an artifact built with the wrong form matches nothing and misreports a healthy shortcut.

### Step 2: Inspect existing engine-native shortcuts

For every owned agent, inspect only its existing shortcut at the current engine's native
location:

- **Claude Code:** `<workspace>/.claude/commands/lr-<agent-name>-agent.md`
- **Cursor:** `<workspace>/.cursor/skills/lr-<agent-name>-agent/SKILL.md`
- **Codex:** `~/.codex/skills/lr-<agent-name>-agent/SKILL.md`

If the artifact does not exist, report `not registered` and continue. Do not create it.

Read an existing artifact and classify it:

1. Construct the **current full artifact** from `docs/register-repo.md` and the engine profile for
   the location being inspected, substituting the current `<agent-name>`, the agent directory in
   the form that location requires, repo name, and role description. If the on-disk artifact equals
   it byte-for-byte, report `current` and leave it unchanged.
2. If the artifact identifies the owned agent with `boot as agent <agent-name> from <agent-dir>`
   or `from <agent-dir-rel>`
   (allowing its generated final punctuation), report `owned legacy or customized` and rewrite it
   in Step 3. Do not preserve custom paths, frontmatter, or additional instructions: this is a
   framework-owned registered shortcut.
3. If the artifact names another `from <agent-dir>` path, report `collision` and leave it
   unchanged.
4. Otherwise report `unrecognised`; do not overwrite it, because the artifact does not establish
   that it is a registered shortcut for this agent.

### Step 3: Rewrite only clean legacy shortcuts

For each shortcut classified as owned legacy or customized, generate the current engine-native shortcut
form from `docs/register-repo.md` using the **exact Registered shortcut bootstrap** in the engine
profile belonging to the location being written. Substitute the owned `<agent-name>` and the agent
directory in that location's required form — `<agent-dir-rel>` for a workspace-local shortcut,
`<agent-dir>` only for `~/.codex/skills/`.

The result must contain no plugin-cache path, framework-version path, or absolute
`agent-boot.md` path. It must equal the current full artifact from Step 2, including standard
Cursor and Codex frontmatter; Claude's form is the bootstrap line alone.

### Step 4: Report

Report each category separately:

- `refreshed`
- `current`
- `not registered`
- `collision`
- `unrecognised`

State explicitly that no missing shortcut was created, collisions were preserved, and owned
shortcuts were regenerated even if customized.

## Write Paths

```
(none)
```

The migration writes only workspace-root or personal shortcut artifacts, which are outside
the boot-time repo-relative collision gate. The ownership and known-template checks above
are the protection for those paths.

## Dry-Run Mode

Perform the same inspection without writing. Report:

- `would refresh: <path>`
- `current: <path>`
- `not registered: <path>`
- `would preserve collision: <path>`
- `would preserve unrecognised: <path>`

Do not prompt in dry-run mode.
