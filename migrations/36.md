# Migration — Version 36

## Summary

Version 36 introduces the Lore v1 file structure and deterministic maps. This migration is a
deliberate no-op for existing Lore: legacy and mixed agents remain supported, and a framework
update must not trigger a whole-corpus rewrite.

## Clear Plugin Cache

Refresh the Lore plugin and start a new session before using v36. This release adds a skill,
changes boot and merge procedures, and updates the bundled `lr-core` script.

1. **Claude Code:** `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback).
2. **Cursor:** run `bash /path/to/lore-framework/scripts/cursor-refresh-plugin`.
3. **Codex:** run `bash /path/to/lore-framework/scripts/codex-refresh-plugin`.

## Write Paths

```
(none)
```

## Procedure

1. Do not add frontmatter to existing Lore files during framework update.
2. Do not create a stored Lore map or grooming cursor.
3. Leave legacy, mixed, invalid, and future-version files byte-identical.
4. Continue the normal version update. New Lore files use v1; merge may lazily migrate clearly
   understood touched files; `/lr:groom` provides explicit bounded or whole-Lore conversion.

This no-write migration is idempotent. Its purpose is to make the adoption boundary explicit in
the version walk rather than silently treating a new file format as ordinary release prose.
