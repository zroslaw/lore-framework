# Engine Profile — Cursor Agent CLI

Selected by `lr-core`'s `detect_engine` (reported as `data.engine` by preflight, consumed at
`agent-boot.md` Step 2) when a `cursor-agent` process appears in this session's ancestry, or when
`<framework-root>` lives under `~/.cursor/…`. The Cursor *application* process
(`…/Cursor.app/Contents/MacOS/Cursor`) is deliberately not a signal — another engine running in
Cursor's integrated terminal has it in the ancestry too. Fills the same five bindings as
`claude.md` (the reference profile). **Where a value here conflicts with a shared procedure doc,
this profile wins for that step.**

Empirical basis: local Cursor Agent CLI trials on `cursor-agent 2026.07.01-41b2de7`, 2026-07-05,
using `--plugin-dir` against a local framework copy. Verified facts so far:

- `--plugin-dir` works for local plugin loading.
- User-facing slash invocation works (`/lr-boot lore-architect`). Skill folders live under
  `.cursor-skills/lr-<skill>/` because Cursor shows the folder name in the picker — unlike Claude
  Code, which prepends the plugin name as `/lr:<skill>`. The `.cursor-plugin/plugin.json` manifest
  points skill discovery at that tree only.
- `${CLAUDE_PLUGIN_ROOT}` is empty in this engine path.
- `ps -o args= -p $PPID` is permitted and exposes `cursor-agent` in the parent args.
- Boot and recall work on real Cursor, but the framework otherwise falls back to the Claude
  profile until this engine profile is present.

## Binding values

| Binding | Value on Cursor |
|---|---|
| **framework-root** | `${CLAUDE_PLUGIN_ROOT}` is empty here — never rely on it. Use the absolute path self-located in Step 0. Reuse that resolved path everywhere `<framework-root>` appears. |
| **invocation-syntax** | User-invoked lore skills work as slash commands (`/lr-<skill>`, e.g. `/lr-boot`, `/lr-recall`; per-agent shortcuts remain `/lr-<agent>-agent`) when the framework is loaded through `--plugin-dir` or installed as a Cursor plugin. The `.cursor-plugin/plugin.json` manifest sets `"skills": ".cursor-skills/"` so only the `lr-`-prefixed wrappers load — canonical `skills/<skill>/` remains for Claude Code, while the hidden wrapper tree stays out of Codex's plugin skill crawl. Registered per-agent shortcuts are workspace-local skills under `.cursor/skills/`, generated by `/lr-register-agent` or `/lr-register-repo`, and path-scoped to the matching repo. When the plugin is not loaded, read `.cursor-skills/lr-<skill>/SKILL.md` (see § Mid-session fallback) — do not guess `docs/<skill>.md` paths. When loaded, invoke the skill by name or follow the same wrapper path for file-driven execution. |
| **subagent-spawn** | Use Cursor's native **`Task`** tool for **merge** (`process-merge.md`) and for procedures where subagent independence is the semantics (currently `trilens-loop.md`). `Task` accepts a free-text brief plus a `subagent_type` (verified in-session 2026-07-28). For merge: spawn one write-capable `Task` per active agent (`generalPurpose` / equivalent), brief it to boot as that agent and run `process-merge.md`, fan out in parallel when there are several agents, collect summaries. **Still serial host-side** for the other optimization-class fan-outs — recall / lore-search, consult, attach version-reconcile, and conflict resolution — until those get their own `Task` upgrade. See § Native subagents and § Host-Side Override Rules. |
| **memory-file** | `AGENTS.md`. |
| **runtime-bounding** | No verified Claude-style Bash-tool `timeout` parameter is assumed here. Rely on Cursor's own job/approval controls plus the fast-fail git env vars in the shared docs. Ignore prose that specifically says to set a Bash-tool timeout parameter. |

## Capability gates

- **engine-detection** — `ps -o args= -p $PPID` works here and exposes the parent `cursor-agent`
  command line. Use it as the strongest runtime signal for Cursor CLI sessions.
- **teammate-detection** — **ignore the verdict; always treat a Cursor session as a normal host
  session.** Claude Agent-Teams semantics do not apply here, so whatever the probe reports carries
  no meaning on Cursor. `spawn-teammate` remains Claude-only. This is stated as "ignore the result"
  rather than "do not run the probe" on purpose: the probe runs inside the same `lr-core preflight`
  call that *determines* which engine you are on, so nothing can suppress it in advance without
  already knowing the answer it is being called to produce. `ps` works here, so the verdict comes
  back `no` rather than `unknown`; both mean host session, so the distinction never reaches a
  decision.
- **git / network approvals** — Cursor CLI exposes `--force`, `--trust`, and sandbox controls at
  launch. In ordinary sessions, auto-pull / push may still be approval-gated or denied. Lore
  procedures must degrade cleanly on denial rather than treating it as a framework failure.
- **parallel worktrees** — Cursor has its own worktree support (`--worktree`, and broader
  parallel-agent features in the product), but the framework has **not yet validated** how that
  interacts with Lore's workspace invariant. Merge uses in-session `Task` fan-out (not
  worktrees). Keep conflict-resolution and other still-serial file work host-driven until proven.
- **native subagents** — available via `Task`; free-text briefs work; **merge** uses them. See
  § Native subagents.

## Native subagents

Cursor ships subagents. Merge and `trilens-loop` use them; some older fan-outs stay serial on
purpose until upgraded.

Confirmed against Cursor's official docs and changelog, 2026-07-25:

- Subagents shipped in **Cursor 2.4** (2026-01-22), available in *"the editor, CLI, and Cloud
  Agents."*
- The agent dispatches them with a **`Task` tool**. Several can run in parallel.
- **Cursor 2.5** added async subagents and the nesting rule: a subagent may spawn its own subagents,
  but one launched by a subagent cannot spawn further — i.e. one extra level below the top agent.
- Definitions are markdown files with YAML frontmatter — `name`, `description`, `model`, `readonly`,
  `is_background` — under `.cursor/agents/` (project) or `~/.cursor/agents/` (user). Cursor also
  reads `.claude/agents/` and `.codex/agents/`, at both project and user level.
- `cursor-agent --help` shows no spawn flag (checked against `2026.07.20-8cc9c0b`), which is
  expected: `Task` is a model-facing in-session tool, exactly like Codex's `spawn_agent`.

**Free-text briefs — validated 2026-07-28** in a live Cursor session: `Task` accepts a free-text
`prompt` plus a `subagent_type` enum (e.g. `generalPurpose`), and returns the subagent's result to
the caller. Pre-defined agent files under `.cursor/agents/` are optional, not required, for
composing per-invocation merge / trilens briefs. (Named agent files remain available when you want
them.)

Community-sourced, **not** confirmed against an official Cursor changelog:

- CLI support was reportedly broken for a period — the `Task` tool was not injected into the CLI
  agent's toolset, so subagents ran serially inside one context — and reportedly fixed for standard
  accounts in Q1 2026. Forum threads spanning roughly Feb–Apr 2026 describe both the bug and the
  fix; no official changelog entry for it could be located. Treat the bug as real and the fix date as
  unverified. The practical consequence either way: on an old CLI build `Task` may be absent, so a
  procedure that needs it should check rather than assume.

Do not extend `Task` use to the remaining serial-default procedures (recall, consult, attach,
conflict resolution) without their own deliberate upgrade. Merge is already on `Task`.

## Detecting "plugin not loaded"

**Do not use `${CLAUDE_PLUGIN_ROOT}`** — it is always empty on Cursor, even when the plugin loaded
correctly.

Use: an expected plugin skill (e.g. `/lr-boot`) **not available** in the session skill list. If
skills are listed but show stale content after an upgrade, see `doctor-stale-plugin-cache.md`
(Claude cache) or the refresh contract below (Cursor).

## Registered shortcut bootstrap

When `/lr-register-agent` or `/lr-register-repo` emits a Cursor per-agent shortcut, use this
exact body after substituting the agent values — **as a single unwrapped line** (see
`register-repo.md` § Resolve the shortcut bootstrap for why):

```markdown
Read the `SKILL.md` for the installed `/lr-boot` skill available in this session. Follow its self-location instruction to resolve `<framework-root>`, then read its `docs/agent-boot.md` and boot as agent `<agent-name>` from `<agent-dir>`.
```

Do not substitute an absolute plugin path, a workspace checkout, or a cache-discovery heuristic.
If the active boot skill is unavailable, use the Mid-session fallback below; emitted shortcuts do
not contain that fallback.

## Mid-session fallback (canonical)

When plugin skills are unavailable and the user provides a checkout path:

1. Treat that path as `<framework-root>` (must contain `VERSION`).
2. Read `docs/engines/cursor.md` (this file) for engine bindings.
3. For a requested operation `/lr-<skill>`: read `.cursor-skills/lr-<skill>/SKILL.md` and follow
   it (it delegates to the correct `docs/<procedure>.md`).

**Name mapping is not mechanical** — always use the wrapper SKILL, not `docs/<skill>.md` guesswork.
Examples: `lr-boot` → `agent-boot.md`; `lr-merge` → `process-merge.md`; `lr-register-repo` →
`register-repo.md`.

The user must communicate the checkout path (paste in chat, `AGENTS.md`, or workspace layout). This
path works **before** boot — engine profile selection is optional when executing file-driven.

## Plugin load, refresh, and load surfaces (operational)

### Refresh contract

- Update the checkout on disk (`git pull` or `scripts/cursor-refresh-plugin`).
- **New session required** — no hot-reload:
  - **CLI:** new `cursor-agent --plugin-dir <path>` process
  - **IDE:** new agent chat / restart (exact gesture varies; local-plugins path is D2-dependent)
- Running session without plugin: use § Mid-session fallback above.

Install helpers: `scripts/install-cursor-plugin`, `scripts/cursor-refresh-plugin`. User-facing guide:
`<framework-root>/INSTALL-CURSOR.md`.

### Load surfaces (honest table)

| Surface | Mechanism | Verified |
|---------|-----------|----------|
| Agent CLI | `cursor-agent --plugin-dir <checkout>` | **Yes** (v20+) |
| Local plugins dir symlink | `~/.cursor/plugins/local/lore-framework` | **D2 probe** — opt-in via `install-cursor-plugin --symlink` |
| IDE chat without `--plugin-dir` | Customize / local plugins | **D2 probe** |
| Marketplace | TBD | **Deferred (Tier B)** |

The documented default remains **checkout + `--plugin-dir`** until Tier B marketplace flows are
validated on a given CLI build.

## Merge via `Task` (`process-merge.md`)

Follow the shared merge execution model, with Claude `Agent` swapped for Cursor `Task`:

1. Collect active agents (host + any attached guests), host-first.
2. For each agent, spawn a write-capable **`Task`** (`generalPurpose` or equivalent — merge needs
   Write/Edit/Bash). Brief example: _"Boot as agent `<name>` (repo: `<path>`) per
   `<framework-root>/docs/agent-boot.md`, then run the merge procedure in
   `<framework-root>/docs/process-merge.md` scoped to yourself. Return a short summary of topics
   touched, role changes, and any anomalies. Do not commit — finalize handles that."_
   Inline the absolute `<framework-root>` in the brief.
3. Multi-agent: spawn all merge `Task`s in parallel (one message / concurrent Tasks).
4. Collect summaries; report per-agent success/failure. **Retain each return** for summarize.
5. If `Task` is missing on an old CLI build, say so and stop — do not silently merge in the host
   and call it the Cursor merge path.

## Host-Side Override Rules

Apply these substitutions where a shared doc expects Claude `Agent` fan-out **as an optimization**
and this profile still keeps the serial path. They do **not** apply to merge (above) or to
semantics-class procedures (`trilens-loop.md`).

### Read-only search work (`lore-search.md`, `recall.md`)

1. Enumerate the target agents (host only, or host + guests).
2. For each target agent, search its `lore/` directory **serially** in the host context using
   Read/Grep/Glob.
3. Produce one synthesis per target agent and group the final output by agent.
4. When only the host is active, this reduces to a single direct lore search.

### Consult (`consult.md`)

1. Do **not** spawn a consultant subagent.
2. Discover the consultant repo/agent normally.
3. Run any needed version reconcile **inline** (same repo-scoped `version-check.md` procedure, but
   in the host context).
4. Read the consultant's `role.md`, `lore-context.md`, and targeted lore topics directly.
5. Return the consult synthesis and file pointers in the same output shape the shared doc expects.

### Attach (`attach.md`)

If attach needs a version reconcile, run it **inline** rather than via a general-purpose
subagent. The rest of attach already loads the guest in the host context and does not need a
Cursor-specific change.

### Conflict resolution (`resolve-conflicts.md`)

If finalize hits a push conflict, resolve conflicted agents **serially** in the host context,
one agent subtree at a time. Keep the 3-attempt cap and all existing scope limits.

## Notes

- Cursor has native subagents (`Task`, shipped in 2.4). **Merge** and **`trilens-loop`** use them.
  Free-text briefs are confirmed. Recall / consult / attach / conflict resolution still use the
  older serial host path until deliberately upgraded.
- A green lifecycle run alone does not prove which tool ran. When upgrading another procedure to
  `Task`, check tool-call logs, not only a passing scenario or a model self-report.
