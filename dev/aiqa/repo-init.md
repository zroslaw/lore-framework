# /lr:dev-aiqa-repo-init — Initialize the AIQA sibling repo (BETA)

> **Audience note.** This document is the logic of the `/lr:dev-aiqa-repo-init` skill. Claude runs these steps; the user does not run them manually.

## Goal

Ensure a source repository has its AIQA sibling repo `<repo>-aiqa`, which holds all AIQA configuration, artifacts, and AI-generated tests. Creating it is **gated on explicit user confirmation**.

## Inputs

- **source repo** — the repository under QA. Default: the current working directory's enclosing git repo. The caller (`/lr:dev-ula-file`) may pass it explicitly.

## Procedure

1. **Resolve the source repo** and its name (e.g. `My-Turbo-Boost-Switcher`).
2. **Derive the sibling path** — `<repo>-aiqa` *as a sibling directory* (same parent as the source repo). Example: `…/git-repos/My-Turbo-Boost-Switcher` → `…/git-repos/My-Turbo-Boost-Switcher-aiqa`.
3. **Idempotency check** — if `<repo>-aiqa/` already exists and contains `aiqa.config.yaml`, report "already initialized" and stop. Never overwrite an existing repo.
4. **Confirm with the user.** Show exactly what will be created (the path, that it will be `git init`-ed, the scaffold below) and ask for explicit confirmation. Do not create anything until the user agrees.
5. **On confirmation, scaffold:**
   - `mkdir <repo>-aiqa` and `git init` it.
   - Write `aiqa.config.yaml` (see below).
   - Create the empty `ula/` directory (with a `.gitkeep`).
   - Write a short `README.md` saying this is the AIQA artifact repo for `<repo>`, generated by AIQA.
   - Optional first commit: `AIQA init for <repo>`.
6. **Report** the created location back to the user (and to the caller, if invoked by `/lr:dev-ula-file`).

## `aiqa.config.yaml` scaffold

```yaml
sourceRepoName: My-Turbo-Boost-Switcher
sourceRepoPath: ../My-Turbo-Boost-Switcher   # relative to this -aiqa repo
aiqaVersion: "0"                              # BETA
createdAt: 2026-06-03
```

## Out of scope (future)

- **Initial repo analysis + prioritized file list.** The broader AIQA vision has an "understand the repo, produce a prioritized list of files to analyze" step. That is intentionally *not* part of repo-init — this skill only stands up the repo. The prioritized-list step will be its own skill (likely `/lr:dev-aiqa-analyze`) that writes into this same `-aiqa` repo.
