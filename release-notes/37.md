# Release Notes — Version 37

## Summary

Version 37 completes the workspace layer. It shipped in v25 with a working **consumer** half and no
**producer** half: `workspace-pull` received teammates' descriptor changes, but nothing ever
published them, nothing reported that they were unpublished, and — as it turns out — on Claude Code
nothing was reading the workspace memory file at all.

Five changes:

1. **`/lr:workspace-push`** (new) — commit the framework-managed workspace files and push the
   workspace repo. The missing producer half.
2. **`/lr:workspace-status`** (new) — read-only diagnosis of the workspace: git state, descriptor
   drift, memory-file contract, child-repo hygiene. Every finding names the command that fixes it.
3. **The workspace memory file is now `AGENTS.md` on every engine**, with a one-line `@AGENTS.md`
   import stub in `CLAUDE.md`. This fixes a **silent whole-engine outage**: Claude Code does not read
   `AGENTS.md`, so any workspace carrying only that file gave every Claude Code session *zero*
   workspace memory, with no error anywhere.
4. **`/lr:workspace-init` converges.** One entry point, no mode flags — `--refresh` and
   `--reconfigure` are retired. On an initialized workspace it re-scans, offers what drifted, and
   writes nothing when nothing drifted.
5. **Codex per-agent shortcuts are workspace-local**, at `.codex/skills/lr-<agent>-agent/SKILL.md`.
   They were personal skills in `~/.codex/skills/`, which no publication path could reach; now all
   three engines' shortcuts are ordinary files in the workspace repo and `workspace-push` publishes
   them.

Underneath the first four sits **one deterministic scanner**, `lr-core workspace-scan`. Init observes
with it, status renders it, `/lr:check` #22–#24 consume it, and push takes its path set from it.

**Migration required:** yes, on Codex only — `migrations/37.md` relocates existing Codex shortcuts
out of the home directory. Agent repo *content* is untouched, and on Claude Code and Cursor the
migration reports `not applicable` and `/lr:update` just bumps the version stamp. Existing workspaces
keep working — `/lr:workspace-init` detects a marker-format memory file and *offers* a one-time
conversion.

## Clear Plugin Cache

This release added skills (`workspace-status`), so the existing plugin cache must be refreshed before
Claude Code will see the changes.

1. `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other plugins' caches), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback), or run the workspace's
   `./clear_plugin_cache.sh` if present.
2. Exit your current Claude Code session and start a new one.
3. Verify `/lr:workspace-status` and `/lr:workspace-push` appear in the available-skills list.

If you skip this step, the prior version's skill catalog will continue to load until the cache is
refreshed. See `docs/doctor-stale-plugin-cache.md` for diagnosis.

## What's New

### The four-command workspace surface

```
workspace-init    initialize, or converge an initialized workspace to disk reality
workspace-pull    consume   — pull the workspace repo, clone declared repos, pull every top-level repo
workspace-push    publish   — commit and push the framework-managed workspace files
workspace-status  diagnose  — read-only; every finding names its fix
```

Two existing commands, two new ones, zero renames. "Add a repo" and "add an agent" need no fifth
command: create or clone the thing, then run `workspace-init` — it notices and offers.

### `/lr:workspace-push`

Several framework skills write workspace-root files and none of them commits: `workspace-init` writes
the descriptor, the memory file, `.gitignore` and `README.md`; the `register-agent` family writes
per-agent shortcuts; `/lr:update` migrations regenerate those shortcuts; `workspace-pull` phase 3
appends `.gitignore` lines. Without a publish step those changes sit dirty indefinitely, and a
teammate's `workspace-pull` phase 0 receives a stale descriptor.

`workspace-push` stages **only** the framework-managed paths, by explicit path argument, and lists
every other dirty file as untouched. Committing arbitrary user files automatically is how unrelated
work ships under a generic message.

Two details worth knowing:

- **The plan shows the commits that will ride along**, from `git log --oneline @{u}..HEAD`, not a
  count. A workspace repo can be committed to by something other than the person running the skill —
  another session, or an autonomous Being — so you confirm specific work, not a number.
- **Memory-file diffs are flagged when they extend past the managed sections.** Git commits whole
  files; you are confirming that your own edits ride along.

See `docs/workspace-push.md`.

### `/lr:workspace-status`

Read-only, no network, cheap enough to run any time. Fifteen findings (S1–S15) covering dirty and
unpushed framework files, remote configuration, undeclared and missing repos, `.gitignore` coverage,
off-default branches, worktree inventory, memory-file contract violations, unregistered agents,
declaration conflicts, and Codex shortcuts still sitting in the old home-directory location.

Ends with `workspace clean` when there is nothing to say.

See `docs/workspace-status.md`, which owns the wording and the fix for every finding.

### The memory-file contract (v3)

**`AGENTS.md` is canonical on every engine; `CLAUDE.md` gets a one-line `@AGENTS.md` import.**

This replaces the engine fork (`CLAUDE.md` on Claude Code, `AGENTS.md` elsewhere), which had a
failure mode nobody could see: a workspace with only `AGENTS.md` — the normal result of running
`workspace-init` from Codex or Cursor, or of a teammate cloning such a workspace — gave every
subsequent Claude Code session no workspace memory at all. No error, no warning, and the stale
payload nobody noticed was the symptom.

The behavior was measured, not assumed: Claude Code does not read `AGENTS.md`; it does honor an
`@AGENTS.md` import inside `CLAUDE.md`, composed with any other content in that file, and a missing
import target is inert rather than an error. One payload, one source of truth, no copy-drift
possible. Lifecycle scenario `test_18b` re-verifies the import on every run, because it is engine
behavior rather than a contract.

**Named sections replace the HTML-comment markers.** The payload is now three exact level-2
headings — `## Lore Framework`, `## Repositories`, `## Agents` — each carrying a provenance comment:

```markdown
<!-- lr:managed — regenerated by workspace-init; edits here are overwritten -->
```

A managed section runs from its heading to the next `## `, or EOF. The file reads as a real document
instead of generated goo, and there are no marker pairs to malform. `workspace-init` detects the old
`lr:workspace-init:*` or `lr:init:*` markers and **offers** a one-time conversion; declining keeps
the old format working, and `/lr:check` #23 warns until it is migrated.

The `## Agents` section lists **registered** agents — the "what can I boot here" answer — and the
`register-agent` / `register-repo` / `unregister-agent` / `unregister-repo` skills now maintain it in
the same operation as the shortcut write. Registration remains the single membership authority;
`workspace-init` only renders.

### `/lr:workspace-init` converges

No mode flags. Uninitialized → interview. Initialized → convergence pass driven by the scanner's
findings. Already at canonical state → `already current`, and nothing is written.

`--refresh` and `--reconfigure` are retired; supplying either prints one line and proceeds normally.

Two behavioral additions:

- **The join/found seam is decided by `git merge-base`,** not by counting local commits. A workspace
  with an autonomous writer produces commits nobody typed, so "no local commits" is not evidence of a
  fresh workspace. Unrelated histories are detected and offered an explicit adopt-the-remote path;
  `--allow-unrelated-histories` is never passed automatically.
- **Declining a remote is recorded**, as `sharing: local` in `lore-workspace.md`. Without it, finding
  S3 nags forever about a state the user chose on purpose — and a finding a user can never clear
  teaches them to skim the whole report.

### Codex shortcuts move into the workspace

**`.codex/skills/lr-<agent>-agent/SKILL.md` replaces `~/.codex/skills/lr-<agent>-agent/SKILL.md`.**

Codex loads skills from two roots — the user's home directory *and* the repo you are working in —
and the framework had only ever used the first. That put Codex alone among the three engines:
Claude's `.claude/commands/` and Cursor's `.cursor/skills/` are workspace files that get committed,
reviewed, and cloned, while a Codex teammate joining a workspace arrived with no bootable shortcuts
and no command that could give them any. `workspace-push` said as much in its own docs — no publish
path applies.

There is one now. Registration writes the workspace-local path, `workspace-push` publishes it,
`workspace-pull` delivers it, and `workspace-status` inventories it like the other two.

Two things to know about the repo root, both verified against `codex-cli 0.142.5` rather than assumed
(`docs/engines/codex.md` § Where per-agent shortcuts live records the probe):

- It is **the git root of the session's working directory** — or that directory itself, outside a
  repo. Start Codex at the workspace root and you see the workspace's shortcuts; start it inside a
  child agent repo and you see that repo's, which is the same rule Claude Code's `.claude/commands/`
  has always followed.
- **`~/.codex/skills/` still loads.** Nothing breaks on upgrade day: an un-relocated shortcut keeps
  working locally for the person who has it. It just remains invisible to everyone else, which is
  what finding S15 and `migrations/37.md` are for.

**Migration 37** relocates them, Codex-only and idempotent: for each agent owned by the booting repo,
it rewrites the shortcut at the workspace path and removes the home copy — after verifying the new
one exists. It never invents a shortcut for an unregistered agent, and it never deletes a home
shortcut whose boot line names an agent directory outside this workspace. `~/.codex/skills` is
user-global and agent names collide across repos by design, so an unmatched shortcut is somebody
else's workspace, not litter.

Finding **S15** is repurposed to match: it used to report agent repos with no Codex shortcut on this
machine; it now reports Codex shortcuts still in the home location, flags the ones that are outright
duplicates of a workspace copy, and — unlike its predecessor — is not gated on the running engine,
because the remedy is a workspace-local write that is correct from any of them.

### `lr-core workspace-scan`

One deterministic scan behind all four commands, plus `/lr:check` #22–#24. Emits the standard JSON
envelope with git state, descriptors, children, memory-file state, shortcut inventory, the
framework-managed path set with dirty classification, and the finding list.

It is a **literate accelerator** (`docs/conventions.md` § Script Fallback Contract):
`scripts/lr_core/workspace_scan.py`'s docstrings are the normative procedure for a manual pass.

**The script emits data; the docs own the words.** A finding carries an `id`, a `severity`, and
structured `data` — never a finished sentence. That seam matters: a script string that reads like a
finished message gets printed as one, and printing it *looks* like handling the situation, so the
executor never reaches the doc that owns the remedy.

Every git query is local-refs-only, so `workspace-status` never touches the network. The cost is
that `behind` reflects the last fetch — which is why S14 is informational and says so.

## What Changed

### `workspace-pull`

- **Phase 3 now ignores every child git repo on disk**, declared or not. Declaration governs cloning
  and pulling; ignoring governs safety, and an undeclared clone can be committed into the workspace
  repo just as easily as a declared one.
- **Undeclared top-level repos are named** after phase 4. Such a repo is pulled here but never
  *cloned* for anyone else, so a teammate's fresh checkout will not contain it. Informational; never
  affects the exit code.
- **Phase 0 reports how far behind the root is** when it skips because the tree is dirty. A silent
  skip is indistinguishable from a successful pull in the summary line.

### `/lr:check`

Checks #22–#24 are now thin consumers of one shared scan rather than three prose restatements of the
rules. No renumbering.

- **#22** — extends to the all-child-git-repos rule, and picks up missing declared repos and
  declaration conflicts.
- **#23** — generalizes from "legacy `lr:init` markers" to the whole memory-file contract: either
  marker vocabulary, a payload sitting in `CLAUDE.md`, a missing import stub, missing or duplicated
  headings.
- **#24** — reads the framework-managed path set from the scanner instead of restating it.

All three docs (`check.md`, `doctor.md`, `workspace-status.md`) now carry the same disambiguation
line: `workspace-status` diagnoses this workspace's git and descriptor state; `/lr:check` verifies
content consistency inside agent repos; `/lr:doctor` diagnoses engine and plugin runtime problems.

### Terminology

The shipped docs used *workspace-owned* for two different things eleven lines apart in `check.md` —
the three standard `.gitignore` entries, and the publishable path set. Split and retired:

- **Framework-managed paths** — what `workspace-push` may stage. Defined in code, rendered by docs.
- **Standard ignore lines** — `/.worktrees/`, `/.lr-beings/`, `/.tmp/`, maintained *inside*
  `.gitignore`.

### `lore-workspace.md` schema

One new **optional** key, `sharing: local`, written only when a user declines a remote. Absent means
"not answered yet" and behaves exactly as today. No migration, no rewrite of existing descriptors,
and an older framework reading a newer descriptor ignores the unknown key. Specified in
`docs/conventions.md` § Descriptor Files.

## Upgrading

1. Clear the plugin cache (above) and restart your session.
2. Run `/lr:workspace-status` in your workspace. It will tell you exactly what this release found.
3. Run `/lr:workspace-init`. On a marker-format workspace it offers the memory-file conversion; on a
   Claude Code workspace missing `CLAUDE.md`, this is what restores workspace memory.
4. Run `/lr:workspace-push` to publish whatever the framework has written and never committed.
5. `/lr:update` in each agent repo bumps its version stamp to 37. **On Codex it also runs migration
   37**, relocating that repo's per-agent shortcuts from `~/.codex/skills/` into the workspace; run
   `/lr:workspace-push` afterwards to publish them. No agent-repo *content* changes in this release,
   on any engine.
