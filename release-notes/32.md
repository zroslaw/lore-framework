# Release Notes — Version 32

## Summary

Version 32 makes generated per-agent boot shortcuts **version-agnostic**. A shortcut now pins
only the agent identity and its absolute agent-repository directory. It asks the active engine's
installed boot skill to locate itself and load `docs/agent-boot.md`, rather than embedding a
versioned plugin-cache path. Re-registering a shortcut repairs the obsolete v31-style form.

## Clear Plugin Cache

This release modifies SKILL-referenced registration, check, doctor, and engine-profile
procedures. Refresh the plugin cache before expecting a newly registered shortcut to use the v32
bootstrap.

After upgrading:

1. **Claude Code:** `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback). Exit the current session and start a new one.
2. **Cursor:** run `bash /path/to/lore-framework/scripts/cursor-refresh-plugin`, then start a fresh
   `cursor-agent --plugin-dir /path/to/lore-framework` session.
3. **Codex:** run `bash /path/to/lore-framework/scripts/codex-refresh-plugin`, then start a fresh
   `codex` session.

## What Changed

- `docs/register-repo.md` now emits a concrete bootstrap copied from the active engine profile.
  It contains no plugin cache path, framework version, cache scan, sibling-checkout lookup, or
  symlink.
- Claude, Cursor, and Codex profiles define their own bootstrap binding to their installed boot
  skill (`/lr:boot`, `/lr-boot`, and `lr:boot`, respectively).
- `/lr:check` detects the obsolete absolute `agent-boot.md` cache pin and validates the new
  identity-and-agent-directory shortcut contract. `/lr:doctor` adds
  `doctor-stale-shortcut-bootstrap`, whose repair is simply to re-register the shortcut.

## Compatibility and Upgrade

No migration writes to agent repositories. Existing repositories auto-stamp to version 32 on
their next boot. Existing generated shortcuts are not rewritten automatically: run the appropriate
registration command again for each shortcut you want to heal.

## Validation and Recorded Waiver

Focused static contract tests and the existing lifecycle unit suite passed for this change.

The real per-engine **upgrade-lifecycle regression** was not run against an installed v32
candidate. The user explicitly authorized this local shipment under a recorded gate waiver. This
release is therefore **not gate-green**; the missing regression is a required filed follow-up.
No push is authorized by this waiver.
