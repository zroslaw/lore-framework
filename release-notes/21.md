# Release Notes — Version 21

## Summary

Version 21 adds a **Cursor-prefixed skill tree** inside the canonical plugin so mixed-engine teams
keep one repo. Claude Code continues to load `skills/<skill>/` (`/lr:boot`); Cursor loads
`skills/cursor/lr-<skill>/` (`/lr-boot`) via `.cursor-plugin/plugin.json`.

## Clear Plugin Cache

This release adds skills under `skills/cursor/` and a new `.cursor-plugin/plugin.json`, so the
existing plugin cache must be refreshed before Claude Code will load the new catalog.

After upgrading:

1. `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other plugins' caches), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback), or run the workspace's
   `./clear_plugin_cache.sh` if present.
2. Exit your current Claude Code session and start a new one.

If you skip this step, the prior version's catalog loads until the cache refreshes. See
`docs/doctor-stale-plugin-cache.md` for diagnosis, or run `/lr:doctor`.

Stable on Claude Code. **BETA on Codex** and **BETA on Cursor** for the core lifecycle surface.

## What's New

### Dual skill trees (one repo, engine-specific names)

| Engine | Skill path | User invokes |
|---|---|---|
| Claude Code | `skills/<skill>/` | `/lr:<skill>` (plugin namespace) |
| Cursor | `skills/cursor/lr-<skill>/` | `/lr-<skill>` (folder name) |

Cursor docs require the skill folder name to appear in the picker; Claude Code prepends the plugin
name automatically. The cursor wrappers are thin pointers to the same `docs/*.md` procedures as the
canonical skills.

Regenerate cursor wrappers after adding or renaming a canonical skill:

```sh
python3 scripts/sync-cursor-skills
```

`/lr:check` step 21 verifies the two trees stay in sync.
