# Release Notes — Version 39

## Summary

Version 39 adds **transcript-backed reflection**: an opt-in
`$lr:finalize --transcript` mode that can recover durable knowledge from the
parser-retained main-session dialogue after normal model context has compacted.
It changes reflection only. Merge, summarize, commit, and push retain their
existing contracts.

**Migration required:** no. Existing agent repositories need only the ordinary
version-stamp update.

## Clear Plugin Cache

This release adds a script verb and changes SKILL-referenced finalization
procedures, so refresh the installed plugin before using it.

1. **Claude Code:** `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other plugins' caches), or `rm -rf ~/.claude/plugins/cache/` (broader fallback).
2. **Cursor:** run `bash /path/to/lore-framework/scripts/cursor-refresh-plugin`.
3. **Codex:** run `bash /path/to/lore-framework/scripts/codex-refresh-plugin`.
4. Exit the current session and start a new one.

If you skip this step, the previous plugin's finalization procedure remains in
effect. See `docs/doctor-stale-plugin-cache.md` for diagnosis.

## What Changed

### Verified transcript evidence

- `session-takeover --find-by-uuid` now accepts `--require-verified`, which
  rejects its normal newest-log heuristic when no candidate contains the
  marker. Transcript finalization marks the current session twice, resolves
  only a verified native log, and retries once without widening its 50-log
  search bound.
- `session-takeover reflection-input` turns an already verified Claude, Codex,
  or Cursor log into private, normalized, user-led dialogue chunks. It reuses
  the existing parsers and bounded tool summaries; it does not introduce a
  second transcript parser or preserve raw logs.

### Private, bounded worker input

- Chunks are written with private permissions beneath the ignored workspace
  scratch root, and the writer refuses any output directory that is not a
  direct child of a `.tmp/lr-finalize` root. The output directory must be new;
  existing paths and symlinks are rejected, and failed writes clean up only
  paths created by the invocation. Each chunk claims its path exclusively and
  never overwrites, but that is atomic path creation, not atomic content: a
  process killed mid-write can leave a partial chunk, which the procedure's
  Cleanup section now covers.
- Chunks retain complete dialogue units, use one labelled-unit overlap, record
  exact rendered character counts, and flag rather than truncate an oversize
  chunk. Cursor's omitted `[REDACTED]` assistant turns are counted and surfaced
  in the finalization report.
- The new `docs/process-transcript-reflection.md` requires host-only sessions,
  fresh read-only worker contexts, complete manifest coverage, one retry for a
  missing or malformed worker result, an 8000-word aggregate limit, sensitive
  data exclusion, exact-file scratch cleanup, and then ordinary reflection
  files for the existing merge phase.

### Finalization surface

- `docs/finalize.md` routes `--transcript` to the focused reflection procedure
  and rejects unknown flags. Normal finalization remains on the existing inline
  reflection path.
- The finalize skill and generated Cursor wrapper advertise `[--transcript]`.

## Validation

- **Deterministic suite green: 432 discovered, 384 run, 48 real-engine
  lifecycle tests skipped** (they need `LR_LIFECYCLE=1`, and the next bullet
  records that they were not run). Coverage includes strict versus
  heuristic resolution, native marker discovery across Claude/Codex/Cursor,
  dialogue-unit grouping, overlap packing, oversize preservation, Cursor
  redaction accounting, exact rendered-size accounting, output-path/symlink
  rejection, partial-write cleanup, CLI validation, and procedure routing. All
  15 new transcript-reflection tests were red against `lr--v1.38.0` and green
  against the v39 candidate. Review then added 3 more to that file (18 total):
  2 for round 1's containment and coverage guards, red against the candidate;
  and 1 for the redirected-scratch-root case round 2 found, red against round
  1's tree. Each was verified red against the tree that preceded its fix and
  green after it.
- **Not run:** real-engine lifecycle and quality suites, by explicit user
  direction for this release. This release makes no model-execution-fidelity or
  quality-benchmark claim.
- **Multi-lens TriLens review: three rounds, nine cold lenses, all reporting.**
  Round 1 read the candidate (literal-executor fidelity, fail-closed and
  privacy containment, lifecycle-seam integration): 15 findings, 13 applied.
  Round 2 read the resulting fixes (fix verification, claim audit, guard blast
  radius): 7 findings, all applied — two of them defects round 1's own fixes
  introduced, including a containment guard that refused the correct path
  wherever the scratch root is a symlink. Round 3 read the twice-edited surface
  (regression sweep, whole-artifact cold read, downstream-operator view): 13
  findings, 12 applied and 1 declined — again including defects from round 2's
  fixes, among them a Cleanup rule that had drifted from the containment
  semantics round 2 had just changed. Two findings are accepted and
  deliberately unfixed: candidate text gets no secret-pattern scan, and no
  engine exposes a parameter that mechanically sandboxes a worker to
  read-only. Both are model judgement, stated as such throughout.
- **The loop ended at its three-round ceiling, not on a clean round.** Every
  finding was applied or consciously declined, but round 3's own fixes are
  themselves unreviewed and no reviewer returned clean on the shipped tree.
  "All findings applied" is not "a round came back clean."
- "Verified" throughout means the run-id marker string was found in the
  candidate log — a literal content match, not a structural or cryptographic
  guarantee.
