# Release Notes — Version 38

## Summary

Version 38 is a correctness pass over the workspace layer v37 shipped. No new commands, no schema
changes, nothing to migrate — a review of the released v37 found defects that a reader of the prose
could not have seen, and this is the fix set.

The theme is **two implementations of one rule drifting apart**. The workspace layer derives a
directory name from a repository URL, and parses `repos:` declarations, in two places: the Python
scanner that *reports* on the workspace, and the bash script that *acts* on it. Where those two
disagreed, the user was told one thing and got another — a repo cloned correctly and then reported
missing forever, with no error anywhere to explain it.

Four fixes and one new finding:

1. **A repeated `repos:` block no longer discards the first block's URLs.** The Python parser reset
   its list on every block header; the awk parser did not. A descriptor with two `repos:` blocks —
   a hand-merge artifact, or a conflict resolved by keeping both sides — silently lost everything
   declared in the first one, and those repos then read as *undeclared* (S5) despite being declared.
2. **A trailing ` # comment` on a declared URL is stripped, as the awk parser already stripped it.**
   Without this, the comment was baked into the URL, its derived directory name matched nothing on
   disk, and a correctly cloned repo was reported missing (S6) forever.
3. **A repository whose derived directory name would start with a dot is refused**, on both sides.
   The scanner skips dot-directories, and so do the `*/` globs that maintain `.gitignore` and
   enumerate pull targets — so cloning `.hidden` produced a repo that was pulled once and then never
   seen again. It is now reported as an unsafe name (S13) instead of silently created. The bash side
   also gained the backslash rejection the Python side already had: `\` is an escape character in
   `.gitignore`, so the line written for such a name never matched the directory it was written for.
4. **`/lr:workspace-push` commits by explicit pathspec.** It staged only framework-managed paths and
   then ran a bare `git commit`, which commits the whole index — so anything another session had
   staged rode along. In a workspace that runs concurrent and unattended sessions, that is a
   routine occurrence rather than a hypothetical.

**New finding S16 — the workspace repo is on a detached HEAD.** The scanner recorded this state from
the start and no finding ever read it. It is the one root git state that makes the rest of the
report go *quiet* rather than loud: a detached HEAD has no upstream, so S2 (ahead) and S14 (behind)
cannot fire, and their silence means nothing. Meanwhile a commit made there belongs to no branch and
the next checkout drops it. **S8 was widened** to the same effect for child repos, which were exempt
from the off-branch check whenever they were detached — silently excusing the worse of the two
states it exists to catch.

**Migration required:** no. Nothing on disk changes shape; `/lr:update` bumps the version stamp.

## Clear Plugin Cache

This release changes `scripts/` and several SKILL-referenced procedure docs, so the existing plugin
cache must be refreshed before your engine will see the changes.

1. **Claude Code:** `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other
   plugins' caches), or `rm -rf ~/.claude/plugins/cache/` (broader fallback).
2. **Cursor:** run `bash /path/to/lore-framework/scripts/cursor-refresh-plugin`.
3. **Codex:** run `bash /path/to/lore-framework/scripts/codex-refresh-plugin`.
4. Exit your current session and start a new one.

If you skip this step, the prior version's scanner and procedure docs continue to load. See
`docs/doctor-stale-plugin-cache.md` for diagnosis.

## What Changed

### Scanner and puller agree again

- `parse_frontmatter` (`scripts/lr_core/common.py`) keeps accumulating into a list key that appears
  more than once, and strips an unquoted trailing ` # comment` from block-sequence items — both
  matching `workspace-pull`'s awk parser, which is the point: these two parse the same declarations
  to answer the same question, so a rule only one of them applies is a defect by construction.
- `derive_dirname` (`scripts/lr_core/workspace_scan.py`) and `url_to_dir` (`scripts/workspace-pull`)
  both refuse a leading dot and an embedded backslash.

### Detached HEAD is no longer invisible

- **S16** (new, `warn`): the workspace root is on a detached HEAD. Names the commit, says why the
  ahead/behind lines above it cannot be trusted, and blocks `/lr:workspace-push`, whose "on a
  branch" precondition now names S16 explicitly.
- **S8** (widened): a child repo on a detached HEAD is reported, with or without a known default
  branch. Being on no branch is off the production state whatever the default is.
- `/lr:check` #24 (workspace publication state) reports S16 alongside S1–S4.

### Scan warnings

- A descriptor whose frontmatter has no closing `---` now produces a warning on the Python side, as
  it already did on the bash side. The parser degrades by consuming the rest of the file, so prose
  can be read as declarations — the declared-repo set from such a scan is not trustworthy, and
  `/lr:workspace-status` now says so rather than reporting a confidently wrong list.

### Documentation corrections

- `/lr:workspace-init` Step 4 requires a re-read of every file it rewrites in full, immediately
  before writing. Step 1's scan is a snapshot, the interview and confirmation gate can sit for
  minutes, and the scanner never emits file bodies — so a "preserved" body could be a stale copy
  that overwrites a concurrent edit.
- `/lr:workspace-push` documents `.git/index.lock` contention, which a concurrent workspace makes
  reachable rather than theoretical, and states plainly what its pathspec commit does *not* protect
  against.
- `docs/doctor.md` no longer tells users to record workspace quirks in `CLAUDE.md` — under the v37
  memory contract that file is a one-line import stub, so anything written there is invisible to
  Codex and Cursor. That is the exact outage v37 shipped to close.
- Codex's general skill invocation is `$lr:<skill>` everywhere. `QUICKSTART.md`, `FIRST-STEPS.md`,
  `INSTALL-CURSOR.md`, and `docs/doctor-stale-shortcut-bootstrap.md` showed `$lr-<skill>`, which is
  the *per-agent shortcut* form — a Codex user following onboarding typed a command that falls
  through to the shell.

## Validation

- **TriLens: three rounds, nine independent cold lenses, all nine reporting.** Round 1 reviewed the
  released v37 through concurrency-and-idempotency, hostile-reality input, and three-engine parity.
  Round 2 reviewed the resulting fixes through fix-verification, findings-system integration, and
  cross-implementation equivalence. Round 3 reviewed the frozen release commit through
  release-artifact integrity, executor simulation, and a claim audit.

  Each round found defects introduced by the previous round's own fixes. Round 2: a blank line that
  broke the findings table so the new S16 row would not render, a paragraph made unreachable by a
  precondition that already handled the case, and two overstated claims in the new prose — corrected
  rather than defended. Round 3: a re-read instruction that could not be executed because no step
  established the baseline it compared against, and — sharpest of all, given this release's theme —
  the new dirname rules left undocumented in `docs/workspace-pull.md`, the very doc that finding S13
  tells users to consult. One rule drifting between sites, relocated from code into prose.

  **The loop ended at its three-round ceiling, not on a clean round.** Every finding raised was
  applied, but round 3's fixes are themselves unreviewed, and no reviewer has returned a clean
  verdict on the shipped tree. "All findings applied" and "a round came back clean" are different
  claims, and only the first is true here.
- **Deterministic suite green at 414 tests**, up from 387. Every new test was verified to fail
  against the v37 tag before the fix and pass after, so the coverage is load-bearing rather than
  decorative.
- **Not run:** the real-engine lifecycle suite and the quality benchmark, both waived by explicit
  user direction for this release. This release is therefore gated by review and deterministic tests
  only — no claim is made about model-execution fidelity on any engine.
