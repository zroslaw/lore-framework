# v43 — A cloned workspace arrives with `lr` already configured

## Summary

Joining a Lore workspace used to mean installing the plugin by hand on your own machine, once per
engine, before any `/lr-*` command existed. v43 removes that step for two of the three engines:
`workspace-init` now writes committed, project-scope plugin settings, so a teammate who clones the
workspace gets `lr` on their next fresh session without installing anything.

- **Claude Code** — `.claude/settings.json` gains `extraKnownMarketplaces` + `enabledPlugins`.
- **Cursor** — `.cursor/settings.json` gains a `plugins` entry carrying `gitUrl`, so no prior
  marketplace registration is needed.
- **Codex** — unchanged. No project-scope plugin mechanism exists for it
  ([openai/codex#18115](https://github.com/openai/codex/issues/18115) is open upstream). This is
  stated wherever the feature is reported, rather than left as a silent gap.

**Migration required:** no. Existing workspaces stay valid. Run `workspace-init` to add the files;
`workspace-status` reports their absence as the new finding **S18**.

## Clear Plugin Cache

This release adds a bundled script module and changes the `workspace-init` and `workspace-status`
procedures, so the existing plugin cache must be refreshed before the new behavior is available.

1. **Claude Code:** `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other
   plugins' caches), or `rm -rf ~/.claude/plugins/cache/` (broader fallback).
2. **Cursor:** run `bash /path/to/lore-framework/scripts/cursor-refresh-plugin`.
3. **Codex:** run `bash /path/to/lore-framework/scripts/codex-refresh-plugin`.
4. Exit the current session and start a new one.

If you skip this step, the prior `workspace-init` procedure may continue to load. See
`docs/doctor-stale-plugin-cache.md` for diagnosis.

## What Changed

### Project-scope plugin settings

- New `lr-core workspace-plugin-config --workspace <path> [--dry-run]` writes both files and reports
  a per-file `created` / `updated` / `unchanged` / `error` action.
- `workspace-init` Step 4 calls it; Step 9 reports the outcome, including Codex's absence.
- Both paths join `MANAGED_PATHS`, so `workspace-push` publishes them.

These two files are the first managed paths whose content is mostly **not the framework's** — they
carry the team's own permissions, hooks, and env. Three guarantees follow from that, and all three
are enforced in code rather than asked of a model:

- **Merge, never rewrite.** Only our own keys are touched; everything else is re-serialised verbatim,
  and a file is rewritten only when a key was actually added.
- **An existing value for our keys is never overwritten.** `"lr@lore-framework": false` is a
  deliberate choice. Converging it back to `true` would make that choice unstickable, so it is kept
  and reported instead.
- **An unparseable file is refused, not clobbered.** Cursor accepts comments and trailing commas
  where strict JSON does not; a file that will not parse is reported as an error and left untouched.

### New finding S18

`workspace-status` reports missing or unreadable project-scope plugin settings as **S18** (info),
fixed by `workspace-init`. A plugin explicitly disabled by the user is reported as context, never as
drift — routing someone to a fix that undoes their own choice is worse than staying quiet.

### Cursor install documentation

`INSTALL-CURSOR.md` was rewritten ahead of this release to make the marketplace install the primary
path, with `--plugin-dir` demoted to framework development. It now carries the verified click paths
for both the Cursor app and `cursor-agent`, and an explicit warning against hand-editing
`~/.cursor/plugins/cache/.cloud-plugin-manifest.json`, which is a server-side cache rather than an
install record.

## Verification

- 39 new unit tests (`tests/test_plugin_config.py`), covering the merge, idempotency, preservation
  of unrelated keys, the four refusal cases, dry-run, and the S18 wiring. Shown red against
  `lr--v1.42.0` and green against this tree.
- Existing suites re-run with no regressions: `test_lr_core`, `test_lr_core_lore_v1`,
  `test_workspace_scan`, `test_workspace_refresh`, `test_shortcut_bootstrap_contract`,
  `test_style_skills`.
- The lifecycle suite and `/lr:trilens-loop` **did not run** — waived by the user for this release.
  Independent subagent review was run in their place. What that leaves untested: real-engine
  execution of the changed `workspace-init` procedure. The code path is covered by unit tests; the
  *procedure text* instructing a model to call it is not.

## Known Limits

- Codex has no project-scope plugin mechanism; nothing is written for it.
- Neither engine hot-reloads. A teammate picks the plugin up on their next fresh session.
- Claude Code applies `extraKnownMarketplaces` only after the teammate trusts the folder.
- The Cursor entry omits `gitRef`, so it tracks the repository's default branch.
