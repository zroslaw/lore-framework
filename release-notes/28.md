# Release Notes -- Version 28

## Summary

Version 28 ships two BETA capabilities:

- **Lore Beings**: autonomous, scheduled lore agents. A *being* is an ordinary lore agent plus a
  `being.md` descriptor declaring existential tasks on a cron schedule; the **Being Keeper**
  (`scripts/lrb.py`, CLI `lrb`) is the deterministic machine-level daemon that spawns headless
  engine sessions on schedule, enforces budget (daily-USD spawn gate + per-task wall-clock kill),
  and tracks state. MVP is CLI-only — no `/lr:` skills yet (`lrb-*` namespace reserved). Three
  engine kinds are supported and e2e-verified: **Claude Code**, **Codex**, and **Cursor**.
- **Session archive + usage**: `/lr:summarize` and `/lr:finalize` now attempt a non-blocking
  Step 1.5 that converts the current native engine log into a lossless gzipped JSONL archive under
  `agents/<agent>/archive/<YYYY>/<MM>/`, and adds `usage:` / `archive:` frontmatter to the host
  session summary when the archive step succeeds.

## Clear Plugin Cache

This release **adds/modifies** bundled scripts (`scripts/lrb.py`, `scripts/session-takeover`) and
SKILL-referenced docs (`docs/beings.md`, `docs/summarize.md`). **Refresh before expecting them to
appear in an installed plugin copy.**

Repo migration required: **no** -- existing agent repos auto-stamp on next boot, and `archive/` is
a purely additive directory created on demand. Cache-clear **is** required to see the new files and
the summarize archive/usage behavior.

After upgrading:

1. **Claude Code:** `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback). Exit the current session and start a new one.
2. **Cursor:** run `bash /path/to/lore-framework/scripts/cursor-refresh-plugin`, then start a fresh
   `cursor-agent --plugin-dir /path/to/lore-framework` session.
3. **Codex:** `codex plugin marketplace upgrade lore-framework` (or `codex plugin add lr@lore-framework`),
   then start a fresh Codex session.

## Status

**Lore Beings is BETA.** The Keeper is built, cross-model reviewed, unit/e2e tested, and
real-engine verified across Claude, Codex, and Cursor — but no being has yet completed the module's MVP success criterion
("the Chronicler lives for a week"), and installing the persistent launchd daemon
(`lrb install --launchd`) remains a deliberate, user-triggered step this release does not perform.

**Session archive + usage is BETA.** The archive script and Step 1.5 behavior are verified on
Claude Code and Codex. Cursor logs can be archived when the script is driven directly, but
`cursor-agent` has been observed to handle the newly inserted summarize Step 1.5 inconsistently:
in some runs it skips the step entirely, and in full-finalize runs it may write a valid `archive:`
block while omitting the paired `usage:` block. The lifecycle test records these as known BETA
doc-following gaps on Cursor, not hard failures for v28.

## What's New

### The Being Keeper (`scripts/lrb.py`, CLI `lrb`)

- One Keeper per machine (`~/.lore-beings/`, override `$LRB_HOME`), serving a registry of
  workspaces; single-threaded ~30s tick loop; single-instance flock; atomic state writes.
- `being.md` descriptor: 5 strict frontmatter keys (`description`, `engine`, `model`, `daily-usd`,
  `existential-tasks`); unexpected keys are config errors; task prompts must stay inside the
  agent directory; schedules are 5-field cron in machine-local time, once-daily per task.
- **Budget = exactly two enforced mechanisms:** the `daily-usd` spawn gate and the per-task
  `timeout-minutes` hard kill (SIGTERM, then SIGKILL of the whole process group after a grace
  period). Missed-fire policy: same-day catch-up (`spawned-late`), dropped past midnight (`missed`).
- **Self-scheduling outbox:** a running session requests a future one-shot via `lrb schedule`
  (within 24h, validated next tick, budget-gated). Accepted files *are* the pending schedule.
- PID-reuse safety: re-adopted sessions are identity-checked (`ps` lstart + command, fetched
  separately) before any signal; unverifiable PIDs are kept visible but never signaled.
- CLI: `install [--launchd]`, `daemon [--once]`, `status [--json]`, `pause`/`resume`, `stop`,
  `engines add|remove|list`, `workspaces add|remove|list`, `schedule`.

### Engine kinds: Claude Code, Codex, and Cursor

Engines are explicit configuration (`lrb engines add`), each with a `kind` — its invocation +
result contract:

- **`claude`**: `CMD -p PROMPT --output-format json --model M`; the result JSON's
  `total_cost_usd` is charged against the daily budget.
- **`codex`**: `CMD exec --json --skip-git-repo-check -m M PROMPT`; JSONL events, outcome from the
  final `turn.completed`/`turn.failed` event, usage tokens recorded. Codex reports no USD, so a
  flat `--session-cost-usd` per session is **required** at `engines add` — keeping the daily-usd
  spawn gate enforceable rather than silently dead.
- **`cursor`**: `CMD -p PROMPT --output-format json --model M --plugin-dir D --workspace W --trust`
  (plus `--force --sandbox disabled` when `permission_mode: full`). `--plugin-dir` is required so
  Lore skills are available to the spawned session. Real `cursor-agent` responses omit
  `total_cost_usd`, so `--session-cost-usd` is required for cursor too.

### Session archive (`scripts/session-takeover archive`)

- New `archive <session-id|path> -o <out.jsonl.gz> --stats <stats.json> --lore-uuid <uuid>
  --engine <engine>` verb writes a gzipped JSONL archive plus a stats JSON.
- New `--find-by-uuid <uuid> --engine <engine>` discovery mode resolves the current native session
  log by the UUID printed into its transcript, with a newest-log heuristic fallback.
- Claude, Codex, and Cursor parsers now additively capture untruncated `raw_args` / `raw_result`
  and per-message timestamps where the engine exposes them. The existing takeover digest remains
  clipped and sidechain-free.
- Claude sidechain/subagent turns are included in the archive and usage totals; they remain
  excluded from takeover digests.

### Session usage (`docs/summarize.md` Step 1.5)

- Host summary frontmatter can now include `usage:` (`models`, `models_source`, `tokens`,
  `cost_usd`, `cost_source`) and `archive:` (`path`, `schema_version`).
- Cost is computed for known Claude models from the documented pricing table; Codex and Cursor are
  reported as `cost_source: unavailable` rather than guessed.
- The step is additive and non-blocking. If native-log resolution or archive writing fails,
  summarize/finalize continues and omits both blocks rather than writing partial metadata.
- Known Cursor BETA gap: Cursor may omit the `usage:` block even when it writes a valid `archive:`
  block; Claude and Codex are strict about writing both together.
- Privacy note: archives preserve raw messages and tool arguments/results. They are committed under
  `agents/<agent>/archive/` by finalize, so users should skip/delete the archive before commit for
  sessions containing secrets or content that should not enter the agent repo.

### Documentation

- `docs/beings.md` — the module reference: descriptor schema, prompt layering, Keeper contract,
  engine kinds, outbox, CLI, MVP concurrency/failure/autonomy policies, and the open headless
  permission-mode gap (a `default`-permission engine cannot approve a being's Bash/Write calls
  headlessly; `full` permission mode is an explicit per-engine user decision).

## Verification

- Focused Keeper unit tests include codex/cursor engine-kind contract tests, process-tree kill
  hardening, launchd plist generation, and PID-identity edge cases.
- Real-engine e2e through the actual Keeper tick loop: `claude`/haiku, `codex`/gpt-5.4-mini, and
  `cursor`/composer. The keeper-specific lifecycle suite now covers 11 of 13 designed scenarios,
  including codex/cursor process-tree kill probes.
- Session archive unit tests cover raw capture, sidechain inclusion, Codex cumulative token
  parsing, gzip roundtrip, stats/cost enums, and UUID-based log resolution. Lifecycle finalize
  scenarios 12 and 13 assert archive + usage frontmatter end-to-end.
