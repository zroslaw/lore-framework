# Release Notes — Version 17

## Summary

Version 17 sharpens how `/lr:merge` (and therefore `/lr:finalize`) maintains each agent's **`lore-context.md`**. The merge step now applies a **shape discipline**, not just a size budget: `lore-context.md` is the agent's every-session working knowledge and the **entry point to the lore graph — not an index of all topics**. It carries compacted, present-tense knowledge plus references to the most important / summary topics, and lets the knowledge graph (summary topics → detail topics) and the on-demand `lore/` scan carry the rest.

The motivating drift: with only a size ceiling, `lore-context.md` tended to accrete a flat enumeration of every topic (a de-facto index) and per-version "vN did X" narrative history — making it large, hard to read, and costly at every boot (boot loads exactly this file). v17 makes the merge **restructure toward shape**, not merely summarize older entries.

## Status

Stable. Release-notes-only — **no migration required**. The new discipline applies incrementally: the next time an agent is finalized (`/lr:merge` / `/lr:finalize`), its `lore-context.md` is reshaped toward the discipline. Nothing on disk changes until then, and no topics are lost — topic discovery has always been the on-demand `lore/` scan, not the context's enumeration.

## Clear Plugin Cache

This release modifies SKILL.md-referenced docs (`docs/process-merge.md`, `docs/conventions.md`) whose runtime behavior changes, and bumps the plugin manifest `1.16.0` → `1.17.0`. The plugin cache holds the prior versions of these docs, so refresh it before the new merge behavior takes effect.

After upgrading:

1. `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other plugins' caches), or `rm -rf ~/.claude/plugins/cache/` (broader fallback), or run the workspace's `./clear_plugin_cache.sh` if present.
2. Exit your current Claude Code session and start a new one.
3. Verify: a subsequent `/lr:merge` shapes `lore-context.md` toward working-knowledge + summary-topic references (no full topic index, no version-history narrative).

If you skip this step, `/lr:merge` keeps following the prior (size-only) guidance until the cache refreshes. See `docs/doctor-stale-plugin-cache.md` for diagnosis, or run `/lr:doctor`.

## What Changed

### `lore-context.md` shape discipline (`docs/process-merge.md` § Step 4)

Merge Step 4 now directs the *shape* of `lore-context.md`, not just its size:

- **Compacted, present-tense working knowledge** the agent uses across most sessions.
- **References to summary topics, not enumerations of detail topics** — point at a theme's summary topic and let it fan out. If a significant theme has no summary topic, create one (strengthening the graph's mid-tier) rather than inlining the whole cluster.
- **No version-history narrative** — "vN did X" belongs in git, release notes, or the topic itself.
- **Preserve graph navigability** — when removing something from `lore-context.md`, keep it reachable from a summary topic the context references.
- **Shape over size** — the 50K budget remains, but nearing it is a drift signal to *restructure*, not merely to summarize older entries.

### `docs/conventions.md` § Lore Context

Redefined: `lore-context.md` is an entry point, not a catalog. The section now points at `docs/process-merge.md` § Step 4 for the maintaining procedure (single canonical source — the procedure lives in one place, not restated here).

## Upgrade Checklist

1. **Clear the plugin cache** (above) and start a fresh session.
2. Optionally reshape an existing agent's `lore-context.md` immediately by running `/lr:merge` (or `/lr:finalize`) for it — or just let it happen at the next finalization.
