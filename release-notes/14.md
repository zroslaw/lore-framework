# Release Notes — Version 14

## Summary

Version 14 is a **correctness fix** to the v13 auto-pull mechanism, plus a new tooling convention that prevents the class of bug behind it.

v13 documented the boot-time pull as running "with a short timeout (60 seconds is reasonable)." The natural implementation — wrapping the command in the `timeout` binary — **fails on macOS/BSD**, where `timeout` (and `gtimeout`) are not installed by default. The result: `timeout 60 git …` exits 127 (`command not found`), the pull aborts, and boot drops into degraded mode for an entirely spurious reason. In effect, **v13 auto-pull silently never ran on macOS** — the most common dev platform — even though the feature appeared shipped.

v14 fixes `docs/auto-pull.md` to bound the pull with the agent's own tool-level timeout (portable, no external binary), hardens SSH remotes against prompt-hangs (which `GIT_TERMINAL_PROMPT=0` never covered), and adds a **Portable Shell** tooling convention so framework-authored commands stop assuming a GNU userland.

**Repo migration required:** no — but a cache-clear is required to make the corrected boot/attach/merge auto-pull behavior take effect. See **Clear Plugin Cache** below for the mandatory action.

## Clear Plugin Cache

This release **modifies SKILL.md-referenced docs** (`docs/auto-pull.md`, invoked from boot, attach, pre-merge, and `/lr:pull-lore`; and `docs/check.md`, the `/lr:check` catalog), a **bundled script** (`scripts/workspace-sync`), and `docs/conventions.md`. It also bumps the plugin manifest version `1.0.0` → `1.14.0` — the first release to do so (see *Plugin manifest version now tracks releases* below). The plugin cache holds the prior copies, so it must be refreshed before Claude Code will run the corrected procedure.

After upgrading:

1. `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other plugins' caches), or `rm -rf ~/.claude/plugins/cache/` (broader fallback), or run the workspace's `./clear_plugin_cache.sh` if present.
2. Exit your current Claude Code session and start a new one.
3. Verify: boot any agent on macOS — auto-pull should now run (a `pulled <N> commit(s)` line when there's anything to pull) instead of reporting a spurious `command not found` failure.

If you skip this step, the v13 copy of `auto-pull.md` keeps loading and the non-portable timeout guidance stays in effect. See `docs/doctor-stale-plugin-cache.md` for diagnosis; if behavior still looks wrong after a clear, run `/lr:doctor`.

## What's Fixed

### Auto-pull no longer assumes a GNU `timeout` binary

`docs/auto-pull.md` § Step 2 previously read "with a short timeout (60 seconds is reasonable)" — which invited a `timeout 60 git …` wrapper. On macOS/BSD that binary doesn't exist, so the pull failed with exit 127 before it ever ran.

The corrected procedure:

- **Bound the pull with the Bash tool's own timeout parameter**, not a `timeout` / `gtimeout` wrapper. This is portable across platforms and needs no external binary.
- **Harden SSH remotes:** `GIT_TERMINAL_PROMPT=0` only suppresses Git's own HTTP(S) credential prompts — it does nothing for SSH. v14 adds `GIT_SSH_COMMAND='ssh -o BatchMode=yes -o ConnectTimeout=10'` so an unknown host key or passphrase prompt fails fast instead of hanging. The tool-level timeout remains the backstop for a mid-transfer network stall.
- **HTTPS remotes are covered too.** The credential-prompt case is already handled by `GIT_TERMINAL_PROMPT=0` (its original purpose — an HTTPS pull without cached credentials fails in ~0.5s rather than blocking on a username prompt), and the **tool-level timeout is the transport-agnostic backstop** bounding any remaining stall (HTTP connect-hang, GUI credential-helper popup) on any remote type. An optional `-c http.lowSpeedLimit=1000 -c http.lowSpeedTime=15` fast-fails a stalled HTTPS transfer. `docs/auto-pull.md` § Step 2 now lays the hang-prevention out per transport.

### New convention: `docs/conventions.md` § Tooling: Portable Shell

Framework-authored shell commands now have an explicit portability rule: assume BSD/macOS userland, avoid GNU-only binaries (`timeout` / `gtimeout` chief among them), and watch BSD-vs-GNU flag differences (`sed -i`, `date -d`, `realpath`, …). Prefer git's own knobs (`GIT_TERMINAL_PROMPT=0`, `GIT_SSH_COMMAND`, `git -C`) over external wrappers. This is the sibling of the existing § Tooling: CWD Safety convention — both are portability landmines hidden inside emitted shell.

### Doc fix: cache-clear footer placement

`docs/conventions.md` § Migration / Release-Note Authoring said to place the Clear Plugin Cache section "near the end (just before See Also)." That contradicted both the worked examples (`release-notes/12.md`, `13.md`, which hoist it directly under the Summary) and the standing authoring discipline. v14 corrects the convention to specify **near the top**, right after the Summary — it's the single mandatory action and must not be buried.

### Plugin manifest version now tracks releases (the cache root cause)

The recurring "stale skill catalog after an upgrade" pain has a root cause: `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` sat frozen at `1.0.0` from v1 through v13. Claude Code identifies a plugin release by that manifest version, so a frozen version means the plugin layer never sees a new release and never refreshes its cache on its own — leaving the manual Clear Plugin Cache step as the only remedy.

From v14 on, the manifest version tracks `VERSION` via the mechanical mapping `1.<VERSION>.0` (v14 → `1.14.0`), codified in `docs/conventions.md` § Plugin Manifest Versioning. It's derived from `VERSION`, so it can't be forgotten — and `/lr:check` now includes **check #19**, which asserts both manifests equal `1.<VERSION>.0` and flags a forgotten bump automatically. Keep clearing the cache for now — bumping the manifest is what lets the platform *detect* a release; whether that alone makes it auto-invalidate is still to be confirmed, so the footer stays as belt-and-suspenders.

### `scripts/workspace-sync` SSH hardening

The bundled sync script set `GIT_TERMINAL_PROMPT=0` (HTTP(S) prompts) but nothing for SSH — so a parallel `git pull --ff-only` against a repo with an unknown host key could hang on an unanswerable prompt. v14 adds `GIT_SSH_COMMAND` with `BatchMode=yes` + `ConnectTimeout=10` (preserving any user-set `GIT_SSH_COMMAND`), bringing the script in line with the new § Tooling: Portable Shell convention — which now also notes that standalone scripts have no Bash-tool timeout and must rely on these fail-fast env vars (or a bash watchdog).

## What Hasn't Changed

- The auto-pull *semantics* — skip non-git / remote-less repos, `--ff-only`, best-effort with degraded-mode on failure, no dirty-tree gate, per-repo scope. v14 only fixes *how the timeout is applied* and *how SSH is hardened*; the contract in `docs/auto-pull.md` is otherwise intact.
- `/lr:pull-lore`, the three auto-pull invocation sites (boot / attach / pre-merge), and all other skills and behaviors.
- Version-stamp procedure, finalization mechanics, descriptor schemas, lore conventions.

## Impact

- **macOS boots now actually auto-pull.** The headline v13 feature works on the primary dev platform for the first time.
- **No action needed for existing repos** beyond the cache clear. No migration, no file regeneration. Repos stamped at v13 auto-stamp to v14 on the next boot via the routine version-check flow — once the cache is refreshed.
- **SSH-remote agent repos** (e.g. `git@github.com:…`) no longer risk a boot hang on first-connect host-key verification; they fail fast and continue in degraded mode instead.
- **Framework authors** have an explicit portable-shell checklist to apply when writing or reviewing any doc or script that emits shell.
- **The cache problem is addressed at its root.** Every release now bumps the plugin manifest version (`1.<VERSION>.0`), which is what lets Claude Code detect a new plugin version at all; the manual cache-clear remains until auto-invalidation is confirmed.

## Upgrade Checklist

1. **Clear the plugin cache** (mandatory — see Clear Plugin Cache above) and start a fresh Claude Code session so the corrected `auto-pull.md` is loaded.
2. Boot any agent on macOS. Confirm auto-pull runs (no spurious `command not found`); a `pulled <N> commit(s)` line appears when there's anything to pull, and the no-op case stays quiet.
3. *(For framework authors)* Review `docs/conventions.md` § Tooling: Portable Shell before writing the next doc or script that emits shell commands.
