# Release Notes -- Version 31

## Summary

Version 31 adds **`scripts/lr-core`** — a deterministic substrate for the mechanical steps that boot,
attach, consult, recall and pull-lore used to execute as prose, one tool call per step. Booting an
agent now runs a single `preflight` command that discovers the agent, auto-pulls its repo, compares
version stamps, and detects an Agent-Teams spawn, then hands back one JSON report. Repeated pulls of
the same repo within a short window are skipped by a TTL cache, which is felt most in fan-outs
(merge, consult, attach) that used to re-pull a repo pulled moments earlier.

It also introduces the **Script Fallback Contract** (`docs/conventions.md`): a shipped script must
never become a single point of failure. Where a script merely accelerates a documented prose
procedure, the agent tells the user it failed and executes that procedure by hand — so a broken
script costs speed, not the outcome. Where a script *is* the specification, the agent reports the
failure and stops that operation rather than improvising a substitute. The procedure docs remain
normative; nothing was deleted.

## Clear Plugin Cache

This release **adds** a script (`scripts/lr-core`) and **modifies** SKILL-referenced docs
(`docs/agent-boot.md`, `docs/attach.md`, `docs/consult.md`, `docs/lore-search.md`,
`docs/pull-lore.md`, `docs/process-merge.md`, `docs/auto-pull.md`, `docs/conventions.md`,
`docs/being.md`, `docs/takeover.md`, `docs/wait.md`, `docs/workspace-pull.md`,
`docs/spawn-teammate.md`, `docs/teammate-conventions.md`, `docs/version-check.md`). Refresh
before expecting the new boot path to run from an installed plugin copy — a stale cache will keep
executing the old prose procedure, which still works but is slower.

Repo migration required: **no** — nothing writes into agent repos; existing repos auto-stamp to 31
on next boot.

After upgrading:

1. **Claude Code:** `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback). Exit the current session and start a new one.
2. **Cursor:** run `bash /path/to/lore-framework/scripts/cursor-refresh-plugin`, then start a fresh
   `cursor-agent --plugin-dir /path/to/lore-framework` session.
3. **Codex:** run `bash /path/to/lore-framework/scripts/codex-refresh-plugin`, then start a fresh
   `codex` session.

## What's New

### `scripts/lr-core` — deterministic substrate

One Python 3 file, standard library only, no `pip install`. Three subcommands:

| Subcommand | What it does |
|---|---|
| `discover` | Enumerate lore agent repos and their agents in a workspace. |
| `preflight` | Resolve an agent, auto-pull its repo (TTL-cached), compare versions, detect a teammate spawn. |
| `scan` | Manifest of an agent's lore topics with titles, git dates, and staleness flags. |

Every subcommand prints one JSON object — `{"ok", "data", "warnings", "errors"}` — and follows a
uniform exit-code contract: **0** means the script ran to completion (degraded conditions such as a
failed pull are reported *inside* `data`, because they are results, not failures), **2** means it
could not complete and the caller must fall back to prose.

Boot's happy path is now: run preflight → act on the report → read `role.md` and `lore-context.md` →
confirm. The script deliberately does **not** inline those two files: interpreting them is the
agent's job, not the script's.

### Pull freshness (TTL cache)

Each successful auto-pull stamps its time inside the repo's git directory (`.git/lr-last-pull` — not
committed, no `.gitignore` change). A subsequent pull within the window (default 600s) is reported
`fresh` and skipped. `--fresh` bypasses it; `/lr:pull-lore` and the pre-merge pull both pass it,
because an explicit refresh should always hit the network.

### `scan` brings age-awareness to recall

`docs/lore-search.md` now generates a topic manifest before dispatching the search subagent, so the
subagent picks what to read by *title* rather than guessing from filenames — and sees how old each
topic is. Findings from topics past the staleness threshold should be flagged as needing
verification. Age is a caution flag, not a disqualifier.

### Script Fallback Contract

New section in `docs/conventions.md`. When a doc delegates to a script and the script fails to
complete, the engine must (1) tell the user in one line which script failed, (2) execute the
canonical prose procedure by hand to the same end state, and (3) diagnose briefly without stalling —
never abort the surrounding flow. A script that exits 0 while *reporting* a problem has succeeded;
that is data, not a takeover trigger.

The contract distinguishes two kinds of script. An **accelerator** has a canonical prose procedure
behind it, so the agent can take over by hand — `scripts/lr-core` is the reference case. An
**implementation** script *is* the specification (`scripts/workspace-pull`, `scripts/session-takeover`,
`scripts/sync-cursor-skills`, `scripts/lr-emit` + `scripts/wait-server.py`, `scripts/lrb.py`); there
is nothing to take over, so the agent reports the failure and stops that operation rather than
improvising an undocumented substitute. `scripts/lrb.py` (the Being Keeper) is the strictest case of
that rule: it enforces budget caps and kill-switches, and a model standing in for it would be exactly
the prompt-theater the Lore Beings design forbids.

## What Changed

- `docs/agent-boot.md` — happy path delegates to `lr-core preflight`; the previous prose steps are
  preserved verbatim as § Manual Boot Procedure, the normative spec and fallback target.
- `docs/attach.md` — guest discovery, pull, and version comparison collapse into one preflight call.
- `docs/consult.md` — host-side existence check uses `lr-core discover` to fail fast on a typo.
- `docs/pull-lore.md`, `docs/process-merge.md` — auto-pull sites call preflight with `--fresh`.
- `docs/lore-search.md` — search briefs carry a `scan` manifest.
- `docs/auto-pull.md` — labelled as the specification `lr-core` implements, and its Step 1 now
  separates "git could not be run" (a failure) from "not a git repo" / "no origin" / bare repo
  (legitimate skips), so the hand-executed fallback reaches the same verdicts the script does.
- `docs/version-check.md` — boot step references renumbered to match the new boot procedure.
- `docs/being.md`, `docs/takeover.md`, `docs/wait.md`, `docs/workspace-pull.md` — one-line Script
  Fallback Contract pointers at their script-delegation sites.
- `docs/spawn-teammate.md`, `docs/teammate-conventions.md` — teammate-rule loading now cites
  `agent-boot.md` Step 2 (was Step 5 before the boot doc was renumbered).
- `docs/conventions.md` — adds § Script Fallback Contract; § Tooling: Non-Shell Runtimes gains the
  deterministic-substrate class alongside the protocol-server one.

## Compatibility

No behavior change for agents or repos. Every flow reaches the same end state as in v30; only the
number of tool calls it takes to get there is different. An install whose `python3` is missing or
whose cache is stale keeps working through the fallback path.
