# Release Notes -- Version 31

## Summary

Version 31 adds **`scripts/lr-core`** — a deterministic substrate for the mechanical steps that boot,
attach, consult, recall and pull-lore used to execute as prose, one tool call per step. Booting an
agent now runs a single `preflight` command that discovers the agent, auto-pulls its repo, compares
version stamps, and detects an Agent-Teams spawn, then hands back one JSON report. Repeated pulls of
the same repo within a short window are skipped by a TTL cache, which is felt most in fan-outs
(merge, consult, attach) that used to re-pull a repo pulled moments earlier.

It also introduces the **Script Fallback Contract** (`docs/conventions.md`): a shipped script must
never become a single point of failure. `scripts/lr-core` is a **literate accelerator**: its
procedure lives in its own instructional comments, not in a separate prose doc, so there is one
artifact instead of two that can silently drift apart. Where a script *is* the specification
instead (no accelerator relationship at all), the agent reports the failure and stops that
operation rather than improvising a substitute. Nothing was deleted — the hand-executable steps
moved from `docs/*.md` files into the functions they describe, and the docs became short pointers
into them.

## Clear Plugin Cache

This release **adds** a script (`scripts/lr-core`) and **modifies** SKILL-referenced docs
(`docs/agent-boot.md`, `docs/attach.md`, `docs/consult.md`, `docs/lore-search.md`,
`docs/pull-lore.md`, `docs/process-merge.md`, `docs/auto-pull.md`, `docs/conventions.md`,
`docs/being.md`, `docs/takeover.md`, `docs/wait.md`, `docs/workspace-pull.md`,
`docs/spawn-teammate.md`, `docs/teammate-conventions.md`, `docs/version-check.md`,
`docs/trilens-loop.md`). Refresh
before expecting the new boot path to run from an installed plugin copy — a stale cache will keep
executing the old prose procedure, which still works but is slower.

Repo migration required: **no** — nothing writes into agent repos; existing repos auto-stamp to 31
on next boot.

After upgrading:

1. **Claude Code:** `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback). Exit the current session and start a new one.
2. **Cursor:** run `bash /path/to/lore-framework/scripts/cursor-refresh-plugin`, then start a fresh
   `cursor-agent --plugin-dir /path/to/lore-framework` session.
3. **Codex:** run `bash /path/to/lore-framework/scripts/codex-refresh-plugin`, then start a fresh
   `codex` session.

## What's New

### `scripts/lr-core` — deterministic substrate

One Python 3 file, standard library only, no `pip install`. Three subcommands:

| Subcommand | What it does |
|---|---|
| `discover` | Enumerate lore agent repos and their agents in a workspace. |
| `preflight` | Resolve an agent, auto-pull its repo (TTL-cached), compare versions, detect a teammate spawn. |
| `scan` | Manifest of an agent's lore topics with titles, git dates, and staleness flags. |

Every subcommand prints one JSON object — `{"ok", "data", "warnings", "errors"}` — and follows a
uniform exit-code contract: **0** means the script ran to completion (degraded conditions such as a
failed pull are reported *inside* `data`, because they are results, not failures), **2** means it
could not complete and the caller must fall back to prose.

Boot's happy path is now: run preflight → act on the report → read `role.md` and `lore-context.md` →
confirm. The script deliberately does **not** inline those two files: interpreting them is the
agent's job, not the script's.

### Pull freshness (TTL cache)

Each successful auto-pull stamps its time inside the repo's git directory (`.git/lr-last-pull` — not
committed, no `.gitignore` change). A subsequent pull within the window (default 600s) is reported
`fresh` and skipped. `--fresh` bypasses it; `/lr:pull-lore` and the pre-merge pull both pass it,
because an explicit refresh should always hit the network.

### `scan` brings age-awareness to recall

`docs/lore-search.md` now generates a topic manifest before dispatching the search subagent, so the
subagent picks what to read by *title* rather than guessing from filenames — and sees how old each
topic is. Findings from topics past the staleness threshold should be flagged as needing
verification. Age is a caution flag, not a disqualifier.

### Script Fallback Contract

New section in `docs/conventions.md`. When a doc delegates to a script and the script fails to
complete, the engine must (1) tell the user in one line which script failed, (2) read the relevant
function's comments in the script and execute those steps by hand to the same end state, and (3) diagnose briefly without stalling —
never abort the surrounding flow. A script that exits 0 while *reporting* a problem has succeeded;
that is data, not a takeover trigger.

The contract distinguishes two kinds of script. An **accelerator** is **literate**: its procedure
lives in its own instructional comments, so the agent can take over by hand by reading the very
function that failed — `scripts/lr-core` is the reference case. (There is no companion prose copy;
that is the point — see § Literate Accelerator below.) An
**implementation** script *is* the specification (`scripts/workspace-pull`, `scripts/session-takeover`,
`scripts/sync-cursor-skills`, `scripts/lr-emit` + `scripts/wait-server.py`, `scripts/lrb.py`); there
is nothing to take over, so the agent reports the failure and stops that operation rather than
improvising an undocumented substitute. `scripts/lrb.py` (the Being Keeper) is the strictest case of
that rule: it enforces budget caps and kill-switches, and a model standing in for it would be exactly
the prompt-theater the Lore Beings design forbids.

## What Changed

- `scripts/lr-core` — every `cmd_*` function and the helpers it calls (`pull_repo`,
  `compare_versions`, `detect_teammate`, `_resolve_agent`) now carry numbered-step docstrings
  written as freestanding instructions, not code annotations. These comments **are** the
  normative procedure (see § Literate Accelerator below); no behavioral change.
- `docs/agent-boot.md` — happy path delegates to `lr-core preflight`; § Manual Boot Procedure no
  longer restates the steps in prose — it points at `cmd_preflight`'s docstring and the three
  helper functions it names.
- `docs/attach.md` — guest discovery, pull, and version comparison collapse into one preflight
  call; the failure-path pointer names `_resolve_agent`/`pull_repo`/`compare_versions` instead of
  restating their steps.
- `docs/consult.md` — host-side existence check uses `lr-core discover` to fail fast on a typo;
  failure path points at `cmd_discover`'s docstring.
- `docs/pull-lore.md`, `docs/process-merge.md` — auto-pull sites call preflight with `--fresh`;
  failure path points directly at `pull_repo`'s comments.
- `docs/lore-search.md` — search briefs carry a `scan` manifest.
- `docs/auto-pull.md` — cut from 96 to ~85 lines: the hand-executed pull steps (bare-repo
  handling, fail-fast env vars, the TTL stamp) moved into `pull_repo()`'s own comments; this doc
  keeps only what's genuinely caller-side policy (the per-site reporting-verbosity table) plus
  conceptual framing (Worktrees, Invariants, Distinct From) that isn't duplicated by the script.
- `docs/version-check.md` — boot step references renumbered to match the new boot procedure.
- `docs/trilens-loop.md` — **rewritten from 325 lines to 80.** The procedure is unchanged in
  intent (resolve scope → three cold independent reviewers, one per lens → triage and apply →
  repeat with fresh reviewers until a round is clean, ceiling of 3) and the rails it names are
  unchanged (cold-context reviewers only, no host-side fallback, regular-tier reviewer models, the
  disposition ledger carried between rounds, a silent round is not a clean round, never finish on an
  outstanding `BLOCK`, disclose anything you turn off). What is gone is the long-form elaboration:
  the per-engine spawn guidance and the worked examples. What is **new** is an explicit exchange contract — the host
  sends a reviewer only the trees, the changed-file list, a sentence of orientation and its lens,
  and gets back only findings-as-pointers (path, line, signature, a paragraph, a severity) plus a
  verdict. No diffs or file contents cross the wire in either direction, at any scale. **If you rely
  on `/lr:trilens-loop` behaving exactly as it did in v30, re-read the doc before your next run.**
  **Correction carried forward:** the Codex regular-tier reviewer model is **`gpt-5.4`**.
  `release-notes/30.md` named it `gpt-4.5`, which was wrong; v30's notes are left as shipped and this
  entry is the correction of record.
- `docs/being.md`, `docs/takeover.md`, `docs/wait.md`, `docs/workspace-pull.md` — one-line Script
  Fallback Contract pointers at their script-delegation sites (unaffected by the literate-
  accelerator change — these are all Implementation scripts).
- `docs/spawn-teammate.md`, `docs/teammate-conventions.md` — teammate-rule loading now cites
  `agent-boot.md` Step 2 (was Step 5 before the boot doc was renumbered).
- `docs/conventions.md` — § Script Fallback Contract's Accelerator category redefined as
  **literate**: the procedure lives in the script's own comments, not a companion doc (see below);
  § Tooling: Non-Shell Runtimes gains the deterministic-substrate class alongside the protocol-
  server one.

### Literate Accelerator

An accelerator script's procedure now lives in its own instructional comments — docstrings and
inline `# Step N:` blocks written so a reader could execute each step without running the code —
rather than in a separate prose doc. This removes the last drift risk in the accelerator model:
previously the same procedure existed twice (once as code, once as doc prose), and the two could
diverge from each other. `scripts/lr-core` is the first and, so far, only instance. See
`docs/conventions.md` § Script Fallback Contract for the rule, and the lore-architect's
`literate-accelerator-pattern.md` for the fuller writeup.

## Compatibility

No repo migration, and no change to the shape of an agent repo. An install whose `python3` is
missing or whose cache is stale keeps working through the fallback path.

Three behavior changes are worth knowing about, none of them breaking:

- **Pull freshness.** A pull that succeeded within the TTL window (default 600s) is now reported
  `fresh` and skipped, where v30 always hit the network. Attach and consult moments after a boot
  are the common case. Pass `--fresh` (or use `/lr:pull-lore`) to force the round-trip.
- **Teammate detection** now walks up to six process ancestors instead of inspecting only the
  immediate parent, and matches `--agent-id` on a flag boundary. This detects spawns that v30
  missed through a wrapper process; it does not change what a detected teammate then does.
- **`/lr:trilens-loop`** runs from a rewritten, much shorter procedure doc — same rails, far less
  elaboration. See § What Changed.

Auto-pull is also now stricter in one place: a lore repo that is not the root of its own git
repository is `skipped` rather than pulled. In v30 `git -C` walked up and fast-forwarded the
*enclosing* repo while reporting the inner path.

## Verification

- **Unit suite: 51/51 green** (`lore-framework-dev/tests/test_lr_core.py`, stdlib `unittest`, all
  in per-test tempdirs with local-only git remotes — no network). Covers the output contract, the
  discovery/preflight/scan paths, TTL-cache behavior, and the degraded-mode branches.
- **Three-lens review, three rounds.** Cold-context independent reviewers on three lenses —
  hand-executor, adversarial correctness, corpus coherence. Round 1 returned no BLOCKERs and five
  HIGH findings, all confirmed against the real files and fixed; see the list below.
- **Bugs found by review and fixed here**, each now pinned by a regression test: auto-pull
  fast-forwarding the *enclosing* git repo when a lore repo was not its own git root (a mutating
  operation attributed to a path it never touched, under exit 0); `git` killed by a signal
  reported as `skipped — not a git repo` with no warning; committed lore topics with non-ASCII
  filenames reported as never committed (git C-quotes those paths unless `core.quotepath=false`);
  `031` and `31` compared as a version skew, sending the user to reinstall a correct plugin; a
  UTF-8 BOM silently voiding a whole frontmatter block; and the exit-2 payload being
  shape-indistinguishable from a determinate `ok:false` whose documented handling is the opposite.
- **Fallback-path fixes:** § Manual Boot Procedure rejoined the numbered procedure at Step 3,
  skipping the step that reads `version-check.md` and `teammate-conventions.md` — so a hand-executed
  boot silently dropped migrations and the teammate rules. The Script Fallback Contract also gained
  an explicit floor for the case a literate accelerator cannot self-serve: the script file being
  absent rather than merely broken.
- **Real-engine lifecycle suite: not yet run for this release.** The scenarios exist, including one
  that breaks `lr-core` and asserts the engine still boots and tells the user. Run the complete
  catalog per engine before publishing this version.
