# Release Notes — Version 20

## Summary

Version 20 lands the previously validated **Cursor** port into the canonical `lore-framework`
plugin. The same team-shared agent repo can now be driven by **Cursor** alongside **Claude Code**
and **Codex**, using the same `docs/engines/` adapter pattern introduced in v19.

This is intentionally a **conservative** Cursor profile: it adds explicit engine detection,
`AGENTS.md` as Cursor's memory file, and a verified **serial host-side** override for the
procedures that previously assumed Claude-style subagent fan-out. The goal is correctness on the
real engine first, not a Cursor-native redesign.

## Clear Plugin Cache

This release adds a new engine profile (`docs/engines/cursor.md`), updates multiple shared
procedure docs, and bumps the plugin manifest `1.19.0` → `1.20.0`, so the existing plugin cache
must be refreshed before Claude Code will load the new versions.

After upgrading:

1. `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other plugins' caches), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback), or run the workspace's
   `./clear_plugin_cache.sh` if present.
2. Exit your current Claude Code session and start a new one.

If you skip this step, the prior version's catalog loads until the cache refreshes. See
`docs/doctor-stale-plugin-cache.md` for diagnosis, or run `/lr:doctor`.

## Status

Stable on Claude Code. **BETA on Codex** for the core lifecycle, unchanged from v19. **BETA on
Cursor** for the currently implemented Tier-1 lifecycle surface. Release-notes-only — **no
migration required**: all changes are inside the plugin; existing agent repos upgrade on next boot.

## What's New

### Cursor engine profile (`docs/engines/cursor.md`)

The framework now ships an explicit Cursor profile with the same five bindings as the Claude and
Codex profiles:

- `framework-root` via self-location
- slash invocation syntax
- `AGENTS.md` as the memory file
- Cursor-specific runtime-bounding guidance
- a conservative serial host-side override for subagent-dependent procedures

### Boot Step 0 can identify Cursor cleanly

Boot now recognizes Cursor from the parent `cursor-agent` process when `ps -o args= -p $PPID`
is available, and also has a `~/.cursor/…` path fallback. This avoids silently defaulting to the
Claude profile on Cursor sessions.

### Shared docs now point at the Cursor override where needed

The validated framework diff adds Cursor-aware engine notes to the shared procedures that needed
them:

- `docs/attach.md` — version reconcile may run inline in the host context
- `docs/init.md` — `AGENTS.md` is the memory file on Cursor
- `docs/resolve-conflicts.md` — conflict resolution can run serially in the host context

These changes keep the shared procedures canonical while letting the engine profile own the
execution override.

## Validation

The Cursor profile shipped here is the one validated on the real local engine:

- `cursor-agent 2026.07.01-41b2de7`
- model `composer-2.5-fast`
- full implemented lifecycle catalog green (`19/19`) via the lifecycle harness

The important design result is that **Tier-1 parity does not require a Cursor-native subagent
mechanism**. The smaller serial-host claim is enough to make the current lifecycle work.

## Scope

This release lands the Cursor core lifecycle into canonical `lore-framework`. Still deferred on
purpose:

- `lr-wait` / `.mcp.json`
- DF / AIQA
- `migrations/*`
- any stronger Cursor-native subagent design
- validation of Cursor's parallel-agent worktree behavior before advertising parallel support

These remain follow-up work, not regressions. Claude Code behavior is unchanged.

## Conventions established

- **Cursor joins the `docs/engines/<engine>.md` profile set** as a first-class engine target.
- **Serial host-side override is an acceptable Tier-1 port shape** when native fan-out is not yet
  validated.
