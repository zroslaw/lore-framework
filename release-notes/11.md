# Release Notes — Version 11

## Summary

Version 11 introduces **`/lr:workspace-sync`** — a one-command workspace synchronization skill that clones declared repos and pulls every top-level git repo. Bootstrap a fresh workspace and keep an existing one up to date with the same operation.

This release also formalizes the **workspace** vs **domain** distinction: a *workspace* is the parent directory containing one or more agent repos (and any other repos they declare); a *domain* is the conceptual scope of a single agent repo. The framework historically conflated the two terms — v11 begins separating them, starting with `<workspace>` being added to the placeholder vocabulary.

**Migration required:** no. The change is additive — a new skill, a new optional field in `lore-repo.md`, and a hard rename of `/lr:pull-domain` to `/lr:workspace-sync` (no compat alias). Existing repos require no changes.

## What's New

### `/lr:workspace-sync` skill

A new plugin skill — symmetric with the rest of the framework — orchestrates workspace synchronization end-to-end.

```
/lr:workspace-sync
```

The skill calls `${CLAUDE_PLUGIN_ROOT}/scripts/workspace-sync` against the current working directory. The script:

1. **Discovers** every `<workspace>/<subdir>/lore-repo.md`.
2. **Reads** each descriptor's `repos:` list and merges them into a deduplicated set.
3. **Clones** any declared repo that isn't yet present in the workspace.
4. **Pulls** every top-level git repo (existing + freshly cloned) in parallel using `git pull --ff-only`.
5. **Reports** conflicts (remote mismatches, target-not-a-repo, dir collisions, clone/pull failures) at the end with one-line resolution hints per conflict.

Bootstrap and incremental sync are the same operation — on a fresh checkout the script clones everything declared; on subsequent runs it only clones what's missing and pulls the rest.

See `docs/workspace-sync.md` for the full schema, behavior spec, exit codes, and limitations.

### `repos:` field in `lore-repo.md`

A new optional frontmatter field declares what other repos the agent repo expects as siblings in the workspace:

```yaml
---
description: Agents for the activities platform
version: "11"
repos:
  - git@github.com:agoda/activities-web.git
  - git@github.com:agoda/activity-search.git
  - https://github.com/zroslaw/lore-framework.git
---
```

Schema rules:

- **Block-form list only** (`- <url>` per line). Inline-flow form (`repos: [a, b]`) is deliberately not supported — keeps the YAML parser surface tight.
- Entries are remote URLs — anything `git clone` accepts (SSH, HTTPS, git, ssh://). Bare or quoted strings both work.
- The directory name in the workspace is derived from the URL (last path segment, `.git` stripped). `git@github.com:foo/bar.git` → `bar/`.
- The list is optional. A `lore-repo.md` without a `repos:` field declares nothing — the workspace still gets pulled.

### Workspace vs domain — placeholder vocabulary

The framework historically used `<domain>` for the parent directory ("where Claude is run from"). v11 introduces `<workspace>` for that filesystem concept and reframes "domain" (prose, no brackets) as the conceptual scope of a single agent repo.

All framework docs are updated to the new vocabulary in this release — `agent-boot.md`, `attach.md`, `check.md`, `conventions.md`, `create-agent.md`, `create-repo.md`, `init.md`, `spawn-teammate.md`, `summarize.md`, `update.md`, `version-check.md`, `workspace-sync.md`, `worktrees.md`, and the README. The `<domain>` placeholder is retired; if you encounter it in older release notes, read it as `<workspace>`.

### Hard rename: `/lr:pull-domain` → `/lr:workspace-sync`

The previous `/lr:pull-domain` skill is removed. Its responsibilities (pulling all top-level repos in parallel) are now part of `/lr:workspace-sync`'s second phase. There is no compatibility alias.

Old script `scripts/pull-domain` and skill dir `skills/pull-domain/` are deleted.

### Multi-domain workspaces

A workspace can contain multiple lore agent repos. Each declares its own `repos:` list. `/lr:workspace-sync` reads them all, merges into a single deduplicated set, and treats it as the union of what the workspace expects to contain. When the same URL appears in more than one descriptor, it's recorded once.

This is the "multi-domain workspace" pattern: several independent agent repos sitting side by side, each self-sufficient elsewhere, but composed in this workspace for cross-domain collaboration.

## Implementation Notes

The script is Bash 3.2+ compatible (default macOS Bash) — no associative arrays. Parallel clone and pull phases run with output captured per-repo; pulls stream their output prefixed with the repo name in real time.

Defenses applied during initial review:

- **Path-traversal rejection.** Derived dir names of `.`, `..`, empty string, slash-containing, or flag-prefixed (`-...`) are rejected with a conflict report — a hostile descriptor cannot reach into the workspace's parent directory.
- **Argument-injection prevention.** `git clone -- "$url" "$target"` terminates option parsing so a URL starting with `-` is treated as a positional argument, not a flag.
- **Frontmatter anchored to line 1.** Code-fenced YAML examples in body content are not parsed as live declarations.
- **BOM tolerance.** UTF-8 BOM-prefixed descriptors parse correctly.
- **Symlink skip.** Symlinked top-level dirs are skipped during enumeration.
- **ANSI-escape scrub on display.** Control bytes in URLs are stripped before printing summary lines.
- **`--ff-only`** for pulls so divergent local branches surface as failures rather than silent merge commits.
- **`GIT_TERMINAL_PROMPT=0`** so HTTPS auth failures don't deadlock parallel children sharing a TTY.
- **Locale-stable output** (`LC_ALL=C` on git invocations) so the summary's heuristic message detection works under any user locale.
- **Ctrl-C cleanup.** SIGINT/SIGTERM kills in-flight clone children and removes the tmpdir before exiting.

## What Hasn't Changed

- All other skills and behaviors are unchanged.
- Lore topic format, descriptor file schemas (other than the new optional `repos:` field), `lore-context.md` budget.
- Boot flow, finalization mechanics, version-stamp procedure.
- `/lr:check` — no new checks. Validation of the `repos:` field (URL syntax, reachability) is deferred until usage shows what to check.

## Impact

- **No action needed for existing repos.** No migration; no file regeneration. Repos stamped at v10 will auto-stamp to v11 on the next boot via the routine version-check flow.
- **Users wanting workspace synchronization** add a `repos:` block to their agent repo's `lore-repo.md` and run `/lr:workspace-sync` from the workspace root.
- **`/lr:pull-domain` users** should switch to `/lr:workspace-sync`. Same parallel-pull behavior plus the new clone phase. The old skill no longer exists.
- **`/lr:init` payload changed.** The canonical payload header in `docs/init.md` is now "## Lore Framework Workspace" (was "## Lore Framework Domain"). On existing workspaces, the next `/lr:init` will show a diff of the managed section and ask the user to confirm before replacing — the standard `/lr:init` drift protocol. Users who don't want to refresh can leave the old payload in place; it remains accurate.

## Upgrade Checklist

1. Use `/lr:workspace-sync` instead of `/lr:pull-domain` (same parallel-pull behavior, plus a clone phase).
2. *(Optional)* Add a `repos:` block to your agent repo's `lore-repo.md` to declare what should sit alongside it.
3. *(Optional)* Run `/lr:workspace-sync` from a fresh checkout to bootstrap the workspace.
4. *(Optional)* Run `/lr:init` to refresh the framework-managed section in your workspace's `CLAUDE.md` (the v11 payload renames "Lore Framework Domain" to "Lore Framework Workspace"). Show-diff-and-confirm gates the change.
5. No file edits required for migration — the version stamp updates automatically on next boot.
