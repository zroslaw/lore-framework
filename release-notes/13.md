# Release Notes — Version 13

## Summary

Version 13 introduces an **auto-pull mechanism** so booted agents always start with the freshest lore, role, and workdir state from their repo's remote. Three sites pull automatically — boot, attach, and pre-merge — and a new **`/lr:pull-lore`** skill lets users force-refresh active agents' repos mid-session.

The motivating problem: in a team-shared agent repo, another contributor (or another session) can push lore changes between sessions. Without an auto-pull, the host boots from local state that may be days behind. The most damaging window is finalize-merge — integrating reflections into stale lore can re-introduce decisions that the team already revised.

**Repo migration required:** no — but a cache-clear is required to make the new `/lr:pull-lore` skill visible and the updated boot/attach/merge procedures effective. See **Clear Plugin Cache** below for the mandatory action.

## Clear Plugin Cache

This release **adds a new skill** (`/lr:pull-lore`), **adds a new doc** (`docs/auto-pull.md`), and **modifies SKILL.md-referenced docs** (`agent-boot.md`, `attach.md`, `process-merge.md`). The existing plugin cache must be refreshed before Claude Code will see these changes.

After upgrading:

1. `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other plugins' caches), or `rm -rf ~/.claude/plugins/cache/` (broader fallback), or run the workspace's `./clear_plugin_cache.sh` if present.
2. Exit your current Claude Code session and start a new one.
3. Verify `/lr:pull-lore` appears in the available-skills list, and that booting an agent shows a `pulled <N> commit(s)` line when changes are pulled (no-op pulls stay silent at boot to keep the common path quiet).

If you skip this step, the v12 skill catalog will continue to load — the new auto-pull behavior will not run on boot, and `/lr:pull-lore` will not be invocable. See `docs/doctor-stale-plugin-cache.md` for diagnosis. If `/lr:pull-lore` still doesn't appear after a cache clear, run `/lr:doctor` — it will diagnose the stale-plugin-cache ailment and guide recovery.

## What's New

### Auto-pull at three sites

The boot, attach, and merge flows now invoke a shared **auto-pull procedure** before reading lore. The procedure is documented at `docs/auto-pull.md` and is the single source of truth for the per-repo refresh semantics.

What it does, per repo:

1. Skip cleanly if the path isn't a git repo or has no `origin` remote.
2. Run `GIT_TERMINAL_PROMPT=0 git -C <repo> pull --ff-only` (60-second timeout). The terminal-prompt suppression prevents an HTTPS auth dialog from hanging the boot flow indefinitely. *(Corrected in v14 — apply the timeout via the agent's Bash-tool timeout, not a `timeout`/`gtimeout` binary, which is absent on macOS/BSD and fails with exit 127; see `release-notes/14.md`.)*
3. Report the outcome on one line. Failures (non-fast-forward, network, auth) **never abort the surrounding flow** — the agent continues to load in degraded mode with a visible warning.

`--ff-only` is safe even when the working tree is dirty: git refuses to fast-forward if the operation would clobber uncommitted edits, and otherwise advances `HEAD` cleanly leaving the working tree untouched. This is essential for the pre-merge invocation site, where `reflections/` from phase 1 is intentionally uncommitted.

The three invocation sites:

- **`agent-boot.md` Step 2** (new step) — auto-pull the host repo right after discovery, before the version check. Every `/lr:boot` and `/lr-<name>-agent` shortcut benefits.
- **`attach.md` Step 2** (new step) — auto-pull the guest repo before its version reconcile and before reading its `role.md`/`lore-context.md`.
- **`process-merge.md` Step 0** (new step) — defense-in-depth: each merge subagent re-pulls before reading lore, so the freshness contract is visible at the merge site (where stale lore is most damaging) and any boot-pull skip is covered.

### `/lr:pull-lore` skill

User-invoked refresh of all active agents' repos. Use mid-session when you want to be sure your loaded context is current — for example, after a teammate pushes lore updates, or before invoking `/lr:reflect` on a long session.

```
/lr:pull-lore
```

Procedure:

1. Enumerates active agents (host + attached guests). Deduplicates shared repos.
2. Auto-pulls each repo (in parallel — auto-pull is independent per repo).
3. Re-reads each active agent's `role.md` and `lore-context.md` so the pulled changes actually take effect in working memory.
4. Reports a compact per-repo summary; flags material `role.md` or `lore-context.md` deltas inline.

Distinct from `/lr:workspace-sync`: workspace-sync is filesystem-wide (clones missing repos declared in `repos:`, pulls every top-level git repo). `/lr:pull-lore` is scoped narrowly to the agents currently loaded.

See `docs/pull-lore.md` for full details.

### `docs/auto-pull.md`

The per-repo procedure shared across all four sites. Authored as the single source of truth so future sites (e.g., `/lr:consult` if it ever needs freshness) can reuse it without copying logic.

## What Hasn't Changed

- All other skills, behaviors, descriptors, and lore conventions.
- Finalization mechanics (reflect → merge → summarize → commit+push). Auto-pull at merge is additive — it doesn't change the merge process itself.
- Version-stamp procedure (`docs/version-check.md`). That gate refuses on dirty trees because it *writes* to `lore-repo.md`; auto-pull doesn't write file contents and so doesn't need the same gate.
- `/lr:workspace-sync` behavior — still the workspace-wide bootstrap+sync companion.
- `lore-context.md` budget, lore topic format, descriptor schemas.

## Impact

- **No action needed for existing repos.** No migration; no file regeneration. Repos stamped at v12 will auto-stamp to v13 on the next boot via the routine version-check flow — assuming the plugin cache has been refreshed first (see Clear Plugin Cache above).
- **Boot becomes a network operation.** Boot stays quiet on the no-op case — only a `pulled <N> commits` line (or `pull failed — <error>`) produces visible output. `/lr:pull-lore` itself is verbose since it's user-invoked. If the network is slow or unreachable, boot still completes (auto-pull is best-effort) — but in degraded mode, with a visible warning. Sessions that intentionally run offline are unaffected past the warning.
- **Worktrees:** auto-pull refreshes whichever checkout was discovered. From a top-level checkout, it fast-forwards the default branch. From a worktree on a feature branch, a non-fast-forward typically surfaces as a one-line warning — manage feature-branch updates yourself. See `docs/auto-pull.md` § Worktrees.
- **Stale lore at merge time becomes much less likely.** The window between a teammate's push and the host's merge that previously could re-introduce already-revised decisions is closed by the boot-time pull, with the pre-merge pull as a defense-in-depth backup.

## Upgrade Checklist

1. **Clear the plugin cache** (mandatory — see Clear Plugin Cache above) and start a fresh Claude Code session so the v13 catalog is loaded.
2. Boot any agent. The boot output shows a `pulled <N> commit(s)` line when there's anything to pull, and stays quiet on the no-op case.
3. Verify `/lr:pull-lore` appears in `/lr:` autocomplete. Optionally invoke it; the per-repo summary should print verbosely (since `/lr:pull-lore` is user-invoked, no-op repos do print `already up to date`).
