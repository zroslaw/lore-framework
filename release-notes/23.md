# Release Notes — Version 23

## Summary

Version 23 hides Cursor's `lr-` wrapper skills from Codex while keeping them fully available in
Cursor.

## Clear Plugin Cache

This release changes plugin-cached skill layout and runtime docs: it moves Cursor wrappers out of
the shared skill crawl, updates `.cursor-plugin/plugin.json`, regenerates the wrapper tree, and
updates the Cursor/Codex guidance docs. Refresh the plugin cache before expecting the new skill set
to appear reliably.

After upgrading:

1. `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other plugins' caches), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback), or run the workspace's
   `./clear_plugin_cache.sh` if present.
2. Exit your current Claude Code session and start a new one.

Engine-specific refresh after pulling this version:

1. **Codex:** run `codex plugin add lr@lore-framework`, then start a fresh Codex session.
2. **Cursor:** restart `cursor-agent --plugin-dir /absolute/path/to/lore-framework` (or restart the
   Cursor session that loads this checkout).

If you skip the refresh, Codex may keep showing the stale `lr:lr-*` duplicates from the old cached
tree. See `docs/doctor-stale-plugin-cache.md` for diagnosis, or run `/lr:doctor`.

## Status

Stable on Claude Code. **BETA on Codex** and **BETA on Cursor** for the core lifecycle surface.
Release-notes-only — **no migration required**: all changes are inside the plugin; existing agent
repos upgrade on next boot.

## What's New

### Cursor wrappers moved to a hidden plugin path

Cursor's wrapper skills no longer live under `skills/cursor/`. They now live under
`.cursor-skills/`, and `.cursor-plugin/plugin.json` points discovery there:

```json
"skills": ".cursor-skills/"
```

The wrapper commands remain `/lr-<skill>` on Cursor. This is a packaging-only relocation: the
skills still point at the same `docs/*.md` procedures as the canonical `skills/<skill>/` tree.

### Codex no longer shows duplicate `lr:lr-*` skills

Codex was recursively discovering the old Cursor wrapper tree and surfacing a redundant second set
of Lore skills such as `lr:lr-boot`, `lr:lr-check`, and `lr:lr-finalize`. By moving the wrappers
out of the shared crawl path, Codex now exposes only the canonical 27 `lr:*` skills.

### Cursor wrapper generation and checks updated

`scripts/sync-cursor-skills` now generates `.cursor-skills/lr-*/SKILL.md` and removes the legacy
`skills/cursor/` tree. The runtime docs and `/lr:check` parity rules now treat `.cursor-skills/`
as the Cursor wrapper root.

## Verification

Targeted engine verification for this ship intentionally covered only the changed surfaces:

- **Codex CLI:** refreshed `lr@lore-framework`, then ran a real `codex exec` check. Result:
  exactly **27** `lr:*` skills, `has_double_prefixed: false`.
- **Cursor CLI:** ran real `cursor-agent --plugin-dir ...` checks. Result: **27** visible `/lr`
  slash skills, and `/lr-boot lore-architect` still booted successfully.

Claude lifecycle coverage was intentionally skipped for this ship to stay within test limits.
