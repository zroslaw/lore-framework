# v47 — Finalize picks who learns

## Summary

`lr:finalize` now checks, before it saves anything, which agents should keep what the session
learned. Sessions drift: you boot one agent and end up doing another agent's work, you boot the
wrong agent, you never boot one at all, or a consulted agent should remember something. Until now
finalize saved everything into whichever agent happened to be booted, and the agent that owned the
work learned nothing.

Release preparation: VERSION is `47`; all four version-bearing plugin manifests are `1.47.0`.
This release has not been published.

## Clear Plugin Cache

This release changes skill text and adds no skill, so the existing plugin cache must be refreshed
before finalize picks up the new behavior.

1. `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other plugins' caches),
   or `rm -rf ~/.claude/plugins/cache/` (broader fallback).
2. Exit your current session and start a new one.
3. Verify by running `/lr:finalize` at the end of a session: its completion line now reports the
   revision outcome ("revised", "checked, no change", or "skipped").

Codex: follow the plugin-refresh instructions in `INSTALL-CODEX.md`, then restart Codex.
Cursor: follow `INSTALL-CURSOR.md`'s refresh instructions and start a new session.

If you skip this step, the prior version's finalize keeps loading. See
`docs/fix-stale-plugin-cache.md` for diagnosis.

## What's new

Before reflecting, finalize compares the session with each workspace agent's role. It adds, as a
guest, every agent that clearly learned something it will need next time, and it picks as host the
agent the session best belongs to. The booted agent keeps the host role on a close call; it is
replaced only when both the main topic and the main result belong to another agent, and it then
stays on as an ordinary guest. Finalize uses the existing attach and boot procedures for this, so
everything after it — reflect, merge, summarize, commit and push — runs exactly as before. If
nothing was booted, finalize boots the right agent itself; if no agent owns the work, it stops
with `Nothing to finalize: <reason>.` and writes nothing.

When revision is planned and allowed, you see one line before it acts, for example: *Revising this
session's agents before saving what it learned: adding `helper-agent` (the session set the
release calendar); host will be `helper-agent` (most of the work was release planning).* An
already-attached guest can become host by promotion only — no second attach. A session that already
ran in the right agent prints nothing new; only the completion line says "checked, no change". That
line reports what actually happened: "revised" only after a successful boot, attach, or host
promotion — a planned notice does not count if every attachment fails and the original host
remains. When a repo described as confidential is in use, or a proposed automatic addition belongs
to one, finalize changes nothing. It makes that check after selecting the proposed participants but
before booting or attaching, so material never moves across that boundary through revision —
`/lr:attach` remains the manual override. `--transcript` skips revision entirely.

Smaller edits that follow from this: a session summary's host is now the *finalization* host, any
other active agent is recorded as a guest, and `lr:consult` no longer says a consultant can only
learn from a later session — finalize may now add it.
