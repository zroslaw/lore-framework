# Release Notes — Version 35

## Summary

Version 35 replaces the three separate public style commands with one selector:
`/lr:style [selectors...]`.

## Clear Plugin Cache

Refresh the Lore plugin and start a new session before using v35. This release removes skill
entry points, so a stale catalog can still show the old commands.

1. **Claude Code:** `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback).
2. **Cursor:** run `bash /path/to/lore-framework/scripts/cursor-refresh-plugin`.
3. **Codex:** run `bash /path/to/lore-framework/scripts/codex-refresh-plugin`.

## What Changed

- `/lr:style` is now the only public Lore style command.
- With no selector, `/lr:style` enables all three components: `plain`, `dialogue`, and `follow`.
- Use `/lr:style plain`, `/lr:style dialogue follow`, or another exact selector set to choose the
  active components. `/lr:style off` disables them all.
- Every `/lr:style` invocation replaces the prior style set; it never silently layers on a previous
  selection.
- The former `/lr:plain-language`, `/lr:dialogue`, and `/lr:follow-me` commands have been removed
  on Claude Code, Cursor, and Codex. Their behavior definitions remain internal components of
  `/lr:style`.
- `scripts/sync-cursor-skills --check` is now read-only and reports wrapper drift without modifying
  the checkout.

## Compatibility and Upgrade

No user-repository migration is required. This is a bundled plugin command-surface change. Refresh
the plugin cache above so removed commands do not linger in an engine's skill catalog.

## Validation

Validated with focused deterministic contract coverage, wrapper synchronization, and cross-engine
catalog/document checks. The expensive real-engine lifecycle matrix was intentionally not run at
user direction; a TriLens review was not run in this session.
