# v45 — Unified installation health

## Summary

`lr:check` becomes the health entry point for the loaded plugin, agent repos, and workspace.
It replaces `lr:doctor` and `lr:workspace-status`, scripts structural checks, and recommends
pulling repos whose last verified check is more than 24 hours old. Boot and attach also explain
automatic version reconciliation, and boot reports why a workspace refresh ran.

Release preparation: VERSION is `45`; all four version-bearing plugin manifests are `1.45.0`.
This release has not been published.

## Clear Plugin Cache

This release removes two skills and changes `check`. Refresh the installed plugin and start a
new session before verifying the new report:

- Claude Code: refresh the plugin; if the catalog is stale, remove only
  `~/.claude/plugins/cache/lore-framework/` and restart. See `docs/fix-stale-plugin-cache.md`.
- Codex: follow the plugin-refresh instructions in `INSTALL-CODEX.md`, then restart Codex.
- Cursor: follow `INSTALL-CURSOR.md`'s refresh instructions and start a new session.

Verify that `check` reports a plugin layer and that `doctor` and `workspace-status` no longer
appear. An old copy of `check` cannot diagnose the new checks it does not contain.

## Changes

- Summary-first report distinguishes plugin-only, agent-repo, and initialized-workspace states.
  Wrong-directory launches get nearby root suggestions without scanning those roots.
- Plugin checks compare the actual loaded version with published release tags and local copies,
  validate manifest versions and migration declarations, and compare Cursor wrappers against
  their existing generator. `--no-network` skips the bounded release probe.
- Repo checks cover descriptors, agent files, Lore validation and reference cautions, pending
  reflections, uncommitted knowledge, summary age, and shortcut registration/format/name matching.
  Exact counts describe completed mechanical checks; AI summary-accuracy review is separate.
- Per-repo freshness uses recorded successful framework pulls, including clone and no-change
  success. Failed or skipped pulls retain the previous timestamp. Missing evidence is unknown,
  not proof of being current. Manual Git commands may not update the marker.
- `--full` expands details and requests semantic review; `--plugin`, `--repos`, and
  `--workspace` select a layer. Repairs are proposed for approval, never performed by the scan.
- The shared findings catalog replaces duplicate wording. All three manual diagnosis documents
  remain available under `docs/fix-*.md`, including the missing-plugin bootstrap case.
- Workspace-generated instructions and install guides route users to `check`.
- Version reconciliation is announced before it starts, including when attach delegates it.
  Boot reports completed workspace refreshes with the affected repos and the refresh reason;
  unchanged/no-op refreshes stay quiet.

Shared `.agents/skills` adoption remains postponed.

## Upgrade and migration

No v45 repo migration is required: agent files, Lore formats, and registered shortcut templates
are unchanged. The normal update procedure advances `lore-repo.md` to 45 after displaying
these notes; a release-note-only version adds no migration write paths. Earlier migrations
still apply when upgrading from an older repo stamp.

For an existing initialized workspace, run `lr:workspace-init` from its root to regenerate
the managed command list in `AGENTS.md` with `check` in place of `workspace-status`. Review
and publish those workspace changes through `lr:workspace-push` when ready. This workspace
refresh is separate from the per-repo version update.

Repo freshness markers are created lazily by successful framework pulls. Until then, `check`
reports unknown freshness and recommends a pull; it does not seed timestamps or fetch repos.
