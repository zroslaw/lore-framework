# v46 — Workspace sync

## Summary

`lr:workspace-sync` is a new command that reconciles every repository in a workspace in one
pass: it commits Lore that was left uncommitted, merges in what teammates have pushed, publishes
each agent repo to its remote, brings source repos up to date, and prunes dead worktree
registrations. It exists because shared Lore stops flowing long before anything looks broken —
findings sit uncommitted, commits stay unpushed, and one modified file blocks the fast-forward
that `lr:workspace-pull` performs.

Nothing is discarded to make a sync succeed. The command never forces, resets, stashes, cleans,
rebases, or deletes a file, and it stops at genuine conflicts rather than picking a winner.

Release preparation: VERSION is `46`; all four version-bearing plugin manifests are `1.46.0`.
This release has not been published.

## Clear Plugin Cache

This release adds a skill, so the existing plugin cache must be refreshed before the new command
appears.

1. `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other plugins' caches),
   or `rm -rf ~/.claude/plugins/cache/` (broader fallback).
2. Exit your current session and start a new one.
3. Verify `workspace-sync` appears in the available-skills list.

Codex: follow the plugin-refresh instructions in `INSTALL-CODEX.md`, then restart Codex.
Cursor: follow `INSTALL-CURSOR.md`'s refresh instructions and start a new session.

If you skip this step, the prior version's skill catalog keeps loading. See
`docs/fix-stale-plugin-cache.md` for diagnosis.

## What's new

`lr:workspace-sync` classifies each repository and treats it accordingly:

- **Lore agent repos** are committed, integrated and pushed in full.
- **The workspace repo** is integrated and pushed, but only *framework-managed* paths are ever
  staged — `lr:workspace-push` already guarantees that nothing else in that directory is touched,
  and both commands now share the predicate that decides it.
- **Source repos** (no `lore-repo.md`) are only brought up to date — never committed, never
  pushed. Committing somebody's in-progress source work and publishing it is not a service.

Per repository it commits local changes, fetches, merges the tracked branch, pushes, and prunes
dead worktree registrations — in that order. Committing before fetching is what makes the rest
safe: the merge is then between two commits rather than between a commit and a dirty working
tree, so nothing unsaved can be overwritten and an abort always restores an exact prior state.

Every repository ends with one terminal status — `published`, `up-to-date`, `local-only`,
`blocked`, `skipped`, or `not-attempted`. `local-only` means committed but not published:
pending publication, never success.

Flags: `--dry-run` (report the plan, write nothing), `--no-push`, `--prune-worktrees`.

### Conflicts

A conflicting merge is left in progress and reported with its paths. Both sides are already
committed, so nothing can be lost, and the resolution — which needs a reader of the content —
follows the rules in `docs/workspace-sync.md` Step 4, which borrows `docs/resolve-conflicts.md`
only for the agent-lore special case. Re-running the command is the continuation: it recognizes
the merge it left behind, refuses to touch one it did not start, verifies no conflict markers
remain, commits it, and proceeds to the push. There is no `--continue` flag and re-running is
always safe.

### What it refuses to do

Each refusal is reported with its remedy, because a refusal nobody can see is indistinguishable
from a bug:

- Never resumes an operation it did not start — a hand-opened merge, or a stopped cherry-pick,
  revert, rebase or bisect, blocks the repository instead. Ownership of an in-progress merge is
  claimed *before* the merge runs, so an interrupted run still recognizes its own work.
- Never touches a repository whose working tree is configured elsewhere (`core.worktree`). Every
  command runs as `git -C <repo>`, which would otherwise act on that other directory.
- Never creates a branch on a remote. A branch with no upstream is committed locally and reported
  `local-only` with the `git push -u` command to run.
- Never publishes a credential-shaped name (`.env`, `*.pem`, `id_*`, …), a nested git repository
  (tracked submodule or untracked clone), a symlink, a file over 25 MB, or editor debris. These
  are held back, named in the report, and left on disk. A *deletion* is never held: removing a
  file that should not have been committed is the one operation the holds must not block.
- Never prunes a worktree registration whose parent directory is absent (the signature of an
  unmounted volume rather than a deleted worktree) or that holds commits no branch points at.
  Worktree *directories* are removed only under `--prune-worktrees`, and only when clean and
  fully merged.

### Relationship to the neighbouring commands

`lr:workspace-pull` sets a workspace up and fast-forwards it; `lr:workspace-push` publishes the
workspace repo's own managed files; `lr:check` reports without repairing. `lr:workspace-sync` is
the repair, and the only one of the four that commits on your behalf.

## A note on the name

`lr:workspace-sync` existed once before, from v11 to v24, as the clone-and-pull bootstrap that v25
renamed to `lr:workspace-pull`. The name is reused deliberately for this different command; the
old one has not existed for twenty-one versions. `docs/fix-stale-plugin-cache.md` used to cite that
rename by name as its worked example of a stale cache, which would now misdiagnose a v46 user who
correctly sees this command — it cites the v45 `doctor` → `check` replacement instead.

## Gate dispositions

- **Deterministic tests — passed.** 62 new tests in `tests/test_workspace_sync.py` covering the
  publish path, conflicts and resumption, merge ownership, holds, upstream resolution, prune
  safety, refusals, dry run, and push retry against a real race — 20 of them added to pin findings
  from the review rounds below. Whole suite: **635 tests across 18 modules, green**, measured
  against the tree being tagged.
- **`lr:check` — passed** against the tagged tree: no plugin-layer findings, nothing at error
  severity.
- **Dogfooding — passed.** Run for real against this framework's own development workspace, on the
  tagged tree rather than on an earlier state. Its first run, during development, published eleven
  uncommitted Lore files that had been sitting in an agent repo and a set of unpushed commits.
- **Design review — passed.** One cold-context adversarial review of the design before
  implementation; sixteen findings, all triaged, the substantive ones closed in code and pinned
  by tests (foreign-merge resumption, staged-but-unresolved markers, nested-repo gitlinks,
  non-origin upstreams, worktree prune on absent volumes, credential and size holds).
- **Implementation review (`lr:trilens-loop`) — three rounds, nine cold reviewers.** Lenses:
  operator recovery, executable-prose fidelity, implementation-versus-promise; then fix-round
  drift, adversarial data loss, and system fit; then a narrow audit of the second fix batch. The
  blockers it caught, none of which the original test suite could reach: a dry-run crash on any
  repository holding a dead worktree registration, merge ownership claimed after the merge rather
  than before (an interrupted run disowned its own merge permanently), the workspace repo being
  committed in full against `workspace-push`'s documented contract, `core.worktree` redirection
  publishing an unrelated directory, and — found in round three, in round two's own fix batch — a
  shared pathspec filename that dropped already-staged paths from a commit while reporting them as
  committed.

  **Round three's fix is itself unreviewed**, which is what a three-round ceiling guarantees for
  whatever the last round finds. It is covered instead by two regression tests shown red against
  the pre-fix commit and green against the tagged tree, and by reading the commit's contents back
  from git rather than reporting what the command intended to commit.
- **Lifecycle suite (real multi-engine execution) — did not run.** On request since 2026-08-22,
  and not requested for this release. What that leaves untested: whether an executing model
  follows `docs/workspace-sync.md` faithfully on Claude Code, Codex and Cursor — in particular
  the Step 0 announcement, the operation notice, and the conflict-resolution hand-off. The
  command's own behaviour is covered deterministically; its *prose* is not.
- **Quality benchmark — did not run.** Not requested.
