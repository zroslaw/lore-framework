# Release Notes — Version 34

## Summary

Version 34 disables automatic full-session transcript archiving. `/lr:summarize`
and `/lr:finalize` now write only session summaries and optional aggregate usage
metadata; they never copy native engine transcripts into agent repositories.

## Clear Plugin Cache

Refresh the Lore plugin and start a new session before using v34:

1. **Claude Code:** `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback).
2. **Cursor:** run `bash /path/to/lore-framework/scripts/cursor-refresh-plugin`.
3. **Codex:** run `bash /path/to/lore-framework/scripts/codex-refresh-plugin`.

## What Changed

- Summarize and finalize no longer create `agents/<agent>/archive/` directories,
  write full Markdown logs, or add `archive:` frontmatter to session summaries.
- Aggregate `usage:` metadata remains available when the current engine exposes
  a native session log and `session-takeover stats` succeeds.
- `session-takeover archive` remains available as a dormant manual primitive for
  a future explicitly designed archive feature. It is not invoked by summarize
  or finalize.
- Boot and ordinary lore search no longer carry archive-directory guidance.

## Compatibility and Upgrade

No migration is required. Existing archive files and historical summary
frontmatter are preserved unchanged; v34 simply stops creating new ones.

## Validation

Validated with the full deterministic test suite, including dedicated contract
tests for disabled automatic archiving and retained manual archive behavior,
plus a repository-wide active-reference search. Real-engine lifecycle testing
and TriLens review were intentionally not run for this release.
