# Release Notes -- Version 29

## Summary

Version 29 adds **`/lr:being`**, the user-facing command surface for Lore Beings. The Keeper
substrate (`scripts/lrb.py`) remains deterministic and CLI-driven, but users now have one Lore
command for status, help, guided setup, Keeper controls, validation, logs, engine config, workspace
registration, and pause/resume.

## Clear Plugin Cache

This release **adds** a bundled skill (`skills/being/SKILL.md`), a SKILL-referenced doc
(`docs/being.md`), modifies `docs/beings.md`, modifies `scripts/lrb.py`, and updates the README
skill table. **Refresh before expecting `/lr:being` or the new Keeper helper commands to appear
in an installed plugin copy.**

Repo migration required: **no** -- existing agent repos auto-stamp on next boot. Cache-clear
**is** required to see the new skill and script behavior.

After upgrading:

1. **Claude Code:** `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback). Exit the current session and start a new one.
2. **Cursor:** run `bash /path/to/lore-framework/scripts/cursor-refresh-plugin`, then start a fresh
   `cursor-agent --plugin-dir /path/to/lore-framework` session.
3. **Codex:** `codex plugin marketplace upgrade lore-framework` (or `codex plugin add lr@lore-framework`),
   then start a fresh Codex session.

## What's New

### `/lr:being`

- `/lr:being` with no arguments shows a short machine status: Keeper state, paused/resumed,
  configured engines, registered workspaces, beings, running sessions, spend/cap, and recent
  failures.
- `/lr:being help` lists the supported subcommands.
- `/lr:being init [agent]` walks through creating a conservative reflect-only `being.md` and first
  task prompt for an existing agent.
- `/lr:being create [agent]` creates a new lore agent, then immediately runs the being setup flow.
- `/lr:being keeper ...`, `/lr:being engine ...`, and `/lr:being workspace ...` wrap the common
  Keeper operations so users do not need to remember raw `lrb` commands.
- `/lr:being validate` and `/lr:being logs <being>` expose zero-cost diagnostics before users start
  a persistent daemon.

### Keeper CLI helpers

- `lrb validate [--json]` statically checks registered workspaces, configured engines, discovered
  `being.md` descriptors, missing prompt files, and engine references.
- `lrb logs BEING [--tail N] [--json]` shows the ledger path, log directory, and recent ledger
  entries for one being.
- `lrb status --json` now includes configured engine names so `/lr:being` can report accurate
  machine-level metrics.

## Verification

- Added deterministic Keeper helper commands that do not spawn engines or spend API money.
- Added `/lr:being` docs following the existing thin-skill / detailed-doc pattern.
- The Lore Beings real-engine lifecycle scenarios now have a separate dev-test package and runner
  (`tests/lifecycle_beings/`). The suite remains explicit and costly; do not run it unless you
  intentionally set its enable flag.
