# Release Notes — Version 24

## Summary

Version 24 tightens the multi-engine **agent-routing surface**: boot no longer does an unnecessary
teammate probe on Codex and Cursor, registration now works at both the **single-agent** and
**whole-repo** level, and generated direct-boot shortcuts on Cursor and Codex now carry clearer
agent-purpose metadata. It also adds **`/lr:takeover` (BETA)** — continue a session recorded by
another engine with its context restored.

Compared with **v23**:

- **v23** fixed packaging so Cursor wrapper skills stopped leaking into Codex.
- **v24** builds on that stable packaging and improves the day-to-day agent-selection and
  registration experience on top of it.

## Clear Plugin Cache

This release adds new skills, updates existing skill descriptions, and changes runtime procedure
docs that the plugin cache loads. Refresh the plugin cache before expecting the new registration and
routing behavior to appear reliably.

After upgrading:

1. `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other plugins' caches), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback), or run the workspace's
   `./clear_plugin_cache.sh` if present.
2. Exit your current Claude Code session and start a new one.

Engine-specific refresh after pulling this version:

1. **Codex:** run `codex plugin add lr@lore-framework`, then start a fresh Codex session.
2. **Cursor:** restart `cursor-agent --plugin-dir /absolute/path/to/lore-framework` (or restart the
   Cursor session that loads this checkout).

If you skip the refresh, the prior version's skill catalog and procedure docs can remain loaded.
See `docs/doctor-stale-plugin-cache.md` for diagnosis, or run `/lr:doctor`.

## Status

Stable on Claude Code. **BETA on Codex** and **BETA on Cursor** for the core lifecycle surface.
Release-notes-only — **no migration required**: existing agent repos upgrade on next boot.

Existing direct-boot shortcuts remain valid. If you want the new richer Codex/Cursor shortcut
descriptions or Cursor path scoping on already-registered agents, rerun `/lr:register-agent` or
`/lr:register-repo`.

## What's New

### Single-agent registration and unregistration

The framework now exposes two new explicit skills:

- `/lr:register-agent [<lore-agent-repo>] <agent-name>`
- `/lr:unregister-agent [<lore-agent-repo>] <agent-name>`

This makes per-agent shortcut management a first-class flow instead of forcing every registration
action through the repo-wide primitive.

### Repo-wide registration is still available, but clearer

The existing repo-wide commands remain:

- `/lr:register-repo <lore-agent-repo>`
- `/lr:unregister-repo <lore-agent-repo>`

Their descriptions and runtime docs now frame them explicitly as the **whole-repo** form, while the
new single-agent commands cover the incremental case.

### Cursor now has native registered per-agent shortcuts

Registered per-agent shortcuts now cover all three supported engines:

- **Claude Code:** `.claude/commands/lr-<agent>-agent.md`
- **Cursor:** `.cursor/skills/lr-<agent>-agent/SKILL.md`
- **Codex:** `~/.codex/skills/lr-<agent>-agent/SKILL.md`

Cursor shortcuts are generated as path-scoped skills with `disable-model-invocation: true`, so they
stay explicit-only and surface only when the matching repo is relevant.

### Richer routing metadata in shortcut skills

Generated Cursor and Codex shortcut skills now include an intent-oriented `description` derived from
the agent's repo and `role.md` purpose. This gives engine skill pickers a better basis for
distinguishing similarly named agents and supports cleaner routing across boot, attach, and consult
flows.

### Boot no longer does the wrong `ps` work on Codex and Cursor

`agent-boot.md` now separates **engine detection** from **teammate detection** and tells engines to
consult their capability gates before probing for teammate spawn context. On Codex and Cursor, the
teammate probe is now skipped entirely instead of running a known-irrelevant or known-blocked `ps`
command and then ignoring the failure.

### Session takeover across engines (BETA)

New skill `/lr:takeover [<session-id | log-path>]`: continue a session recorded by another
coding engine — or an earlier session on this one — with its context restored. Invoked bare, it
explores recent Codex, Claude Code, and Cursor sessions and asks which one to take over; given a
session id or log path, it takes over directly.

The engine-native log is converted by `scripts/session-takeover` (python3, stdlib-only) into a
markdown **takeover digest** — the conversation with tool calls collapsed to one-line summaries —
which the current session loads as prior context. If the recorded session had booted a lore agent,
the takeover boots the same agent first. Typical use: an interrupted session (rate limit, crash,
engine switch) resumes on whatever engine is available.

Conversion is supported for Codex and Claude Code logs; Cursor chats are discovered and listed but
not yet convertible (content-addressed store, ordering not reverse-engineered). See
`docs/takeover.md`.

### Agent-selection skill descriptions are more intent-oriented

The routing-facing skills (`boot`, `attach`, `consult`, `list-*`, `create-agent`, and the
registration skills) now describe the user intent they serve rather than only the command syntax.
This keeps the skill surface more legible on engines that expose descriptions directly.

## Validation

Validated against the test/benchmark stack in `lore-framework-dev` (2026-07-08):

- **stdlib/unit tests** — green.
- **Lifecycle scenarios** — green on all three engines: Claude, Cursor (after a real `init`
  `CLAUDE.md`→`AGENTS.md` fix landed in this release), and Codex (registration scenarios skipped —
  not yet isolated on Codex).
- **Quality benchmark** — green on Claude (full treatment success) and Cursor (positive, weaker
  uplift). **The Codex quality leg was not run for this ship** — the Codex account's tokens were
  exhausted at ship time. Codex lifecycle already passed, so the routing/registration behavior is
  execution-validated on Codex; only the Codex *quality-uplift* measurement is deferred. It will be
  run once Codex tokens are available and folded into a later note if it surfaces anything.
