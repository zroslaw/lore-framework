# v41 — Terminal steps that actually happen

## Summary

v40 shipped without its real-engine gates. Running them found one bug wearing four hats: **the
last step of a procedure — the one that publishes or confirms the outcome — was being silently
skipped**, while every earlier step ran correctly.

The work itself was done right each time. Only the reporting or publishing of it went missing,
which is exactly the failure an executor cannot notice on its own, because nothing tied those
steps to anything observable. Two of the four sat in docs whose "best-effort" or "non-blocking"
wording made skipping feel sanctioned.

This release does not rewrite those procedures. It gives each terminal step an **observable
postcondition** — something the executor can check against reality rather than against its own
intent.

## Clear Plugin Cache

This release modified SKILL.md-referenced docs whose runtime behavior changes (`version-check.md`,
`summarize.md`, `style.md`), so the existing plugin cache must be refreshed before Claude Code
will see the changes.

1. `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other plugins' caches),
   or `rm -rf ~/.claude/plugins/cache/` (broader fallback), or run the workspace's
   `./clear_plugin_cache.sh` if present.
2. Exit your current Claude Code session and start a new one.
3. Verify the updated behavior appears (for example, a version-mismatch boot now reports its
   publication outcome).

If you skip this step, the prior version's docs will continue to load until the cache is
refreshed. See `docs/doctor-stale-plugin-cache.md` for diagnosis.

## What Changed

### Boot-time upgrades now actually publish (`docs/version-check.md`)

A boot that reconciled an outdated repo would stamp `lore-repo.md` to the new version and then
continue booting **without committing or pushing it** — leaving the repo dirty and the user
unaware. Reproduced on both Claude and Codex, and confirmed outside the test fixture: the
`chore(lore): update framework to v<F>` commit exists for v37 and v38 and for no version since.

Step 4 previously read as a pure pointer into `docs/update.md`. It now states that stamping is
not the end of the upgrade, clarifies that "best-effort" governs *outcome* and never licenses a
publication that is silently never attempted, and adds a completion check: after Step 4, every
update-owned path must be either committed or dirty *with a stated reason*. Step 5's outcome
line is now mandatory, because a silent boot is indistinguishable from a skipped step.

`docs/update.md` keeps sole ownership of the commit-gate rules; none are restated.

### Summarize attempts its usage step, or says why not (`docs/summarize.md`)

Step 1.5 (usage metadata) was skipped outright — no `session-takeover` call anywhere in the run,
and no warning. The doc permits omitting the `usage:` block when the step *fails*, so the
omission looked legitimate.

"Non-blocking" now explicitly governs failure, not attempt, and an unavoidable skip must surface
as `warning: usage metadata unavailable — <reason>`. Step 8 gained a pre-write check: you should
be able to point at the `session-takeover` calls before assembling the document.

### Standalone summarize stops merging two Learning shapes (`docs/summarize.md`)

For a direct `/lr:summarize` with no reflection or merge, the doc mandates one exact sentence —
but also describes a per-agent bullet block for the cases where phases *did* run, and never said
which wins. Runs merged them, producing per-phase claims backed by no phase evidence. The exact
sentence is now stated to be the entire body of the section.

### `/lr:style` confirms out loud (`docs/style.md`)

The `Style set: ...` confirmation was skipped. Style components change *how* you write, not
*whether* you reply, so silent adoption is indistinguishable from ignoring the invocation. The
confirmation is now named as the skill's only observable result, and ordered first when the same
turn also answers a question.

## Test Harness (dev repo)

Not shipped in the plugin, but the reason this release exists:

- **The Claude lifecycle shard could not run at all.** The plugin-identity gate asked the *model*
  which plugin root supplied its skills. On any machine with the framework installed from the
  marketplace, the model inspects the plugin cache and reports that path, while `--plugin-dir` had
  in fact won — so a correct run was reported as a mismatch and the entire shard refused to start.
  The verdict now comes from the engine's own `system`/`init` event: no model in the loop. It also
  now catches a `plugin.json` version disagreeing with `VERSION`.
- **Keeper self-scheduling (C1)** could never pass on macOS: the fixture registered the logical
  `/var/...` path from `mkdtemp` while `lrb` stores and compares realpaths, so a being's
  self-schedule was always rejected as an unregistered workspace. `lrb` was correct; the fixture
  bypassed the normalization `lrb workspaces add` applies.
- **`test_30`'s prompt was ambiguous**, not the framework — it asked for "the mapped top-level
  area" against a map carrying both a `root:` and an `areas:` list.
