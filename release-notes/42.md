# v42 — Workspaces that stay fresh and explain themselves

## Summary

v42 improves the workspace layer in two connected ways:

- Agent boot now performs a bounded, TTL-guarded refresh of the whole workspace, so sibling repos
  can receive safe fast-forward updates without relying on someone to remember `workspace-pull`.
- `workspace-init` now treats the Repositories and Agents sections of `AGENTS.md` as an AI routing
  map. It investigates weak descriptions, aligns the complete set, and stores improvements in their
  canonical sources instead of generating disposable copy.

**Migration required:** no. Existing workspaces and agent repos remain valid. Run `workspace-init`
when you want to audit and improve an existing workspace's routing descriptions.

## Clear Plugin Cache

This release changes bundled scripts, the boot procedure, and the `workspace-init` skill, so the
existing plugin cache must be refreshed before the new behavior is available.

1. **Claude Code:** `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other
   plugins' caches), or `rm -rf ~/.claude/plugins/cache/` (broader fallback).
2. **Cursor:** run `bash /path/to/lore-framework/scripts/cursor-refresh-plugin`.
3. **Codex:** run `bash /path/to/lore-framework/scripts/codex-refresh-plugin`.
4. Exit the current session and start a new one.

If you skip this step, the prior boot and workspace-init procedures may continue to load. See
`docs/doctor-stale-plugin-cache.md` for diagnosis.

## What Changed

### Automatic workspace refresh during boot

- Preflight refreshes the workspace at most once per 16 hours by default, with overrides to force,
  disable, or change the TTL.
- A filesystem lock prevents concurrent boots from starting duplicate refreshes. State lives under
  the workspace's ignored `.tmp/lr-state/` directory.
- Refresh delegates to the existing `workspace-pull` procedure under a 90-second process bound and
  preserves its fast-forward-only safety model.
- The automatic leg never clones missing repos. It reports `setup-required` and directs the user to
  `workspace-pull`, keeping first-time workspace setup explicit.
- Successful no-op refreshes stay silent. Pulled repos, partial failures, blocked repos, and
  workspace-status findings are surfaced with actionable detail.
- Sessions started inside `.worktrees/` resolve back to the actual workspace root, so all worktrees
  share one refresh state and lock.

### AI-oriented workspace routing map

- Repository and agent descriptions must now explain ownership, useful contents or knowledge, and
  when an unfamiliar agent should inspect, boot, or attach the entry.
- `workspace-init` audits all declared repositories and registered agents as one aligned set. Weak
  entries trigger evidence-based repo investigation, including representative docs, tests, and code
  where needed to establish boundaries between sibling repos and agents.
- Lore repo descriptions remain canonical in `lore-repo.md`; agent descriptions remain canonical in
  `role.md`; ordinary repos use the new optional `lore-workspace.md` `repo-context` block.
- The scanner exposes structured routing inventories and finding S17 for missing, malformed, stale,
  or misplaced canonical descriptions. Duplicate agent names are qualified by repo and shortcut
  membership is resolved by the shortcut's exact target path.
- One scoped approval applies description updates. A separate single publication approval covers
  all affected Git repos, committing narrowly, publishing child repos first, and withholding the
  workspace push if a canonical child description could not be published.
- `create-repo`, `create-agent`, and registration guidance now ask for useful routing descriptions
  from the start, reducing future repair work.
