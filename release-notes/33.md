# Release Notes — Version 33

## Summary

Version 33 automatically refreshes existing, clean legacy per-agent shortcuts during
framework migration. This closes the v32 adoption gap: users no longer need to remember to
re-register a shortcut after upgrading.

## Clear Plugin Cache

Refresh the Lore plugin and start a new session before upgrading, so the v33 migration is
available:

1. **Claude Code:** `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback).
2. **Cursor:** run `bash /path/to/lore-framework/scripts/cursor-refresh-plugin`.
3. **Codex:** run `bash /path/to/lore-framework/scripts/codex-refresh-plugin`.

## What Changed

- Existing shortcuts that identify an owned agent are rewritten to the active-boot-skill form,
  including customized legacy boot paths.
- The migration applies only when the shortcut's embedded `from <agent-dir>` path proves it
  belongs to the repo currently being migrated.
- Missing shortcuts remain missing, and collisions are reported and preserved. Registered
  shortcuts are framework-owned generated artifacts, so customization is replaced on refresh.

## Compatibility and Upgrade

Use a normal boot or update entry once after installing v33:

- **Claude Code:** `/lr:boot` or `/lr:update`
- **Cursor:** `/lr-boot` or `/lr-update`
- **Codex:** invoke the installed `lr:boot` or `lr:update` skill through Codex's native skill
  mechanism; an agent must not type `/lr:<skill>` into its shell.

A legacy direct shortcut that cannot boot cannot repair itself; use the normal entry point for
that first upgrade.
