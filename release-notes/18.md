# Release Notes — Version 18

## Summary

Version 18 adds **`lr-wait`** — an on-demand **wait / sleep / event** primitive for agents, aimed at
background (`claude -p`) or occasionally-watched sessions. It is the *inbound* counterpart to the
outbound signal hooks (`Stop`/`Notification`): a running agent can **pause and resume on time or on
an external event**, where the event carries text (instructions/data) for the agent to act on.
Waiting is **on-demand** — the agent waits only when you instruct it to, never on a normal turn end.

This ships the framework's **first bundled MCP server** and its **first `python3` dependency**
(standard library only — no `pip`).

## Clear Plugin Cache

This release adds a skill (`/lr:wait`), bundled scripts, and a plugin MCP server (`.mcp.json`), and
bumps the plugin manifest `1.17.0` → `1.18.0`, so the existing plugin cache must be refreshed before
Claude Code will see them.

After upgrading:

1. `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other plugins' caches), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback), or run the workspace's
   `./clear_plugin_cache.sh` if present.
2. Exit your current Claude Code session and start a new one.
3. Verify: the `lr-wait` MCP server connects and the `wait_for_event` and `sleep` tools appear (and
   `/lr:wait` is listed).

If you skip this step, the prior version's catalog loads until the cache refreshes. See
`docs/doctor-stale-plugin-cache.md` for diagnosis, or run `/lr:doctor`.

Stable. Release-notes-only — **no migration required**. Adds plugin files only; nothing on existing
agent repos changes.

## What's New

### The `lr-wait` MCP server (`scripts/wait-server.py`)

A pure-stdlib Python MCP stdio server, auto-started from the plugin's `.mcp.json`, exposing two tools:

- **`wait_for_event(name?, mode?, timeout_seconds?, inbox?)`** — block until a matching event file
  appears in the inbox, then return it. `name` filters by event **type** (filename prefix); `mode`
  is `"one"` (oldest single) or `"all"` (drain every pending match); `timeout_seconds` bounds the
  wait (`0` blocks indefinitely). Event **content is plain text by default** (JSON optional).
  Consumed events move to `processed/`.
- **`sleep(seconds)`** — a plain timer. "Wait with a timeout" is `wait_for_event` + `timeout_seconds`.

### Waking an agent (`scripts/lr-emit`)

A bash helper that atomically drops an event into the inbox: `echo "…" | lr-emit --name deploy`.
Anything that can write a file — cron, CI, a webhook adapter, or you — can wake a waiting agent; the
server only ever sees files.

### `/lr:wait` skill + `docs/wait.md`

The documented contract: the two tools, the three consumption modes (one / all / by-name), the
file-inbox event model, inbox location + override, headless usage, and the on-demand rule.

## Conventions established

- **`conventions.md` § Plugin MCP Servers** — declare bundled servers in a root `.mcp.json`;
  `${CLAUDE_PLUGIN_ROOT}` expands; adding a server is cache-affecting.
- **`conventions.md` § Tooling: Non-Shell Runtimes** — `python3` (stdlib only) is allowed for
  protocol-speaking server components where bash is impractical; portable shell stays the default.

## Upgrade Checklist

1. **Clear the plugin cache** (above) and start a fresh session.
2. Confirm `wait_for_event` / `sleep` appear and `/lr:wait` is listed. Optionally: tell an agent to
   "wait for an event," then `scripts/lr-emit --name go <<<'proceed'` from another shell.
