# Release Notes — Version 16

## Summary

Version 16 introduces the **Dark Factory (DF)** module (`df/`) — the lr-dev / SDLC extension of the framework — as **BETA**, and ships its first aspect: **AIQA / ULA** (AI-based Quality Assurance, Unit-Level Analysis).

`/lr:df-ula-file` runs a **single-file ULA pass**: it splits a source file into units and, per unit, one agent runs five ordered steps —

- **A — find bugs** — potential issues in the unit, plus any `crossUnit` findings it notices in neighbours/interactions
- **B — generate test scenarios** — clean-room (without looking at existing tests)
- **C — gap analysis** — scenarios vs. the existing tests, both directions
- **D — verify bugs** — re-investigate each finding for real-ness and *real system impact*; revise `severity`, or move false positives to a preserved `dismissed` list
- **E — guardrail** — confirm every Step A bug was accounted for

After the per-file artifacts are written, an **independent aggregation-level pass** re-verifies all bugs once more with whole-file context. Results persist as YAML into a per-repo **`<repo>-df`** backbone, each artifact carrying a provenance header (`git hash-object` source SHA) so git history serves as the run store.

`/lr:df-repo-init` scaffolds the `<repo>-df` backbone for a source repo (asks before creating).

This is the first version to ship DF with a real manifest version (`1.15.0` → `1.16.0`), so it is visible to the marketplace rather than only via `--plugin-dir`.

## Status: BETA

The DF module is **under active design**. Its layout, skills, prompts, and schemas may change between versions **without a migration** — the `df-` skill prefix, the `<repo>-df` backbone layout, and the artifact schemas are not yet stable contracts. Use it to generate and review analysis; don't build durable tooling against its on-disk shapes yet.

**Repo migration required:** no — v16 is additive (a new module + two new skills). Existing agents, lore, descriptors, and skills are untouched.

## Clear Plugin Cache

This release **adds new skills** (`/lr:df-repo-init`, `/lr:df-ula-file`) and their referenced docs, prompts, and schemas under `df/`, and bumps the plugin manifest `1.15.0` → `1.16.0`. The plugin cache holds the prior skill catalog, so it must be refreshed before Claude Code will see the new skills.

After upgrading:

1. `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other plugins' caches), or `rm -rf ~/.claude/plugins/cache/` (broader fallback), or run the workspace's `./clear_plugin_cache.sh` if present.
2. Exit your current Claude Code session and start a new one.
3. Verify: `/lr:df-repo-init` and `/lr:df-ula-file` appear in the skill list.

If you skip this step, the new skills won't appear. See `docs/doctor-stale-plugin-cache.md` for diagnosis, or run `/lr:doctor`.

## What's New

### The DF module (`df/`) — BETA

The Dark Factory backbone for development / SDLC automation. DF-core init (`df/repo-init.md`) is aspect-agnostic; the first aspect is AIQA (`df/aiqa/`). Per-repo artifacts and narrative context live in a sibling **`<repo>-df`** repo under `repo-lore/<file>/`.

### ULA findings carry impact + classification

Each bug records a deep-technical `description` **plus** a plain-language `impact-summary` readable by any engineer (not only stack specialists), `nature` (`product` = user/UX impact vs `technical` = memory/CPU/leaks/crashes/stability), `severity` (impact if real), `confidence` (how sure it is a bug), and optional `category` / `tags`.

### Verified twice, with history preserved

Bugs are verified once per unit (Steps D/E) and once at aggregation (independent, whole-file). Findings judged not-real are **not deleted** — they move to a `dismissed` list with their original fields, a `dismissal-reason`, and `dismissed-by` (`unit` or `aggregator`), so the false-positive rate stays analysable and a wrong dismissal can be revisited.

### Per-repo `<repo>-df` backbone

Artifacts persist under `repo-lore/<file>/ula/{bugs,scenarios,gap}.yaml`, overwritten each run — git history is the run store; the dedupe key is `source-SHA × config-id`. Each artifact carries a Provenance Header.

## Upgrade Checklist

1. **Clear the plugin cache** (above) and start a fresh session so the new skills load.
2. *(optional, BETA)* Point `/lr:df-ula-file <file>` at a source file to try a ULA pass — it offers to scaffold `<repo>-df` first via `/lr:df-repo-init`.
