# Release Notes — Version 12

## Summary

Version 12 introduces **`/lr:doctor`** — a self-healing skill where the framework carries its own troubleshooting wisdom. The user describes a symptom; the doctor matches it against a catalog of known ailments and applies (or guides) the fix.

The first ailment shipped is **stale plugin cache** — the failure mode where a skill known to exist in the current `VERSION` doesn't appear in the available-skills list because Claude Code's plugin cache is holding the prior version's content. This was the motivating use case for v12 itself: an in-session test where v11's `/lr:workspace-sync` was missing because the cache still held v10.

This release also formalizes the **migration / release-note cache-clear convention**: any version that adds, removes, or renames skills/commands must include a "Clear Plugin Cache" footer telling the user how to make Claude Code pick up the change. This release notes doc itself follows that convention (see below).

**Repo migration required:** no — but a cache-clear is required to make `/lr:doctor` itself visible. See **Clear Plugin Cache** below for the mandatory action.

## Clear Plugin Cache

This release **adds a new skill** (`/lr:doctor`), so the existing plugin cache must be refreshed before Claude Code will see it. This is the only mandatory action for v12.

After upgrading:

1. `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other plugins' caches), or `rm -rf ~/.claude/plugins/cache/` (broader fallback), or run the workspace's `./clear_plugin_cache.sh` if present.
2. Exit your current Claude Code session and start a new one.
3. Verify `/lr:doctor` appears in the available-skills list.

If you skip this step, the v11 skill catalog will continue to load until the cache is refreshed — meaning `/lr:doctor` is itself missing from the very session you'd want to use it in. See `docs/doctor-stale-plugin-cache.md` for diagnosis.

## What's New

### `/lr:doctor` skill

A new plugin skill that diagnoses runtime/environmental framework issues and applies fixes.

```
/lr:doctor                                          # asks for symptom
/lr:doctor my workspace-sync skill is missing       # focused query
```

Procedure:

1. Identify the symptom (from the user's invocation or by asking).
2. Match against the **catalog** in `docs/doctor.md`.
3. Load the matching `docs/doctor-<slug>.md` topic.
4. Run the topic's diagnosis steps to confirm the ailment.
5. Apply the remedy (asking before destructive actions).
6. Verify the symptom is gone.
7. If no ailment matches: tell the user, fall back to manual investigation, and offer to add a new ailment topic during finalization.

The skill is **distinct from** `/lr:check` (content-level consistency) and `/lr:update` (version reconciliation). It targets runtime/environmental issues that escape both — most commonly plugin-cache effects after upgrades, and any future class of issue that surfaces from real-world usage.

See `docs/doctor.md` for the orchestrator and the full catalog.

### Catalog: `docs/doctor-stale-plugin-cache.md`

The first shipped ailment. Symptoms covered:

- A v11+ skill (e.g. `/lr:workspace-sync`) is missing from the available-skills list.
- An old skill name (e.g. `/lr:pull-domain`) still appears after a hard rename.
- A SKILL.md or doc edit doesn't seem to have taken effect.
- A plugin update appears successful but Claude Code reflects the prior version.

Remedy: clear the lore-framework cache (or fall back to the broader cache wipe), exit the current session, start a fresh one, and verify. Detailed commands and a bootstrap note for the chicken-and-egg case (when the skill missing is `/lr:doctor` itself) are in the topic.

The topic also documents the observed cache behavior — Claude Code appears to resolve plugin content through the cache rather than the marketplace, so renames and deletions can leave stale state behind — and points back to the v12 cache-clear convention for prevention.

### Migration / release-note cache-clear convention

`docs/conventions.md` adds a new **Migration / Release-Note Authoring** section. Future `migrations/<N>.md` and `release-notes/<N>.md` whose changes touch plugin-cached state (skills, slash commands, scripts, SKILL.md-referenced docs) must include a "Clear Plugin Cache" section near the end with concrete commands.

Rationale: the cache-stale failure mode is invisible until the user invokes a missing skill and gets confused. Putting the fix in the migration's own line of sight means users don't have to discover `/lr:doctor` after the fact.

## Implementation Notes

- `skills/doctor/SKILL.md` is a thin one-liner pointing at `docs/doctor.md` — same skill-doc pattern as the rest of the framework.
- `docs/doctor.md` carries the orchestrator (matching procedure), the catalog index, and a § What Belongs in the Catalog section that scopes the catalog to universal ailments only.
- Each ailment is its own `docs/doctor-<slug>.md` topic. Adding an ailment is a doc-only change; no script or plugin reload required after the cache is refreshed (which is itself the point of the first ailment).
- The catalog grows by accretion. When users hit a runtime issue not yet covered, the fix is captured during finalization and added as a new topic.

## What Hasn't Changed

- All other skills, behaviors, descriptors, and lore conventions.
- Boot flow, finalization mechanics, version-stamp procedure.
- `/lr:check`, `/lr:update`, `/lr:workspace-sync` are unchanged in behavior. (Both `check.md` and `update.md` gained a one-line cross-reference pointing at `/lr:doctor` for runtime issues — content-level only, no procedure changes.)
- Lore topic format, descriptor file schemas, `lore-context.md` budget.

## Impact

- **No action needed for existing repos.** No migration; no file regeneration. Repos stamped at v11 will auto-stamp to v12 on the next boot via the routine version-check flow — assuming the plugin cache has been refreshed first (see Clear Plugin Cache above).
- **Users hitting `/lr:doctor`-style issues** (skills missing, old commands lingering) now have a structured diagnosis path.
- **Authors of future framework versions** must include the "Clear Plugin Cache" footer when their changes touch cached state. See `docs/conventions.md` § Migration / Release-Note Authoring.

## Upgrade Checklist

1. **Clear the plugin cache** (mandatory — see Clear Plugin Cache section above) and start a fresh Claude Code session so the v12 catalog is loaded.
2. Try `/lr:doctor` next time framework behavior feels off.
3. *(Optional, for framework authors)* When writing a future migration or release-notes doc that changes skills/commands, follow the cache-clear convention.
