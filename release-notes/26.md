# Release Notes — Version 26

## Summary

Version 26 completes **Cursor session conversion** for `/lr:takeover` (BETA). Since v24, Cursor
chats were discoverable but not convertible; this release ships full JSONL transcript parsing plus
`store.db` tool-result pairing via batch-window name matching. Codex and Claude Code behavior is
unchanged. `/lr:takeover` remains **BETA** — internal procedure may still evolve.

## Clear Plugin Cache

This release **modifies** `scripts/session-takeover` and the SKILL-referenced procedure doc
`docs/takeover.md`. **Refresh before expecting Cursor conversion to work reliably.**

Repo migration required: **no** — existing agent repos auto-stamp on next boot. Cache-clear
**is** required.

After upgrading:

1. **Claude Code:** `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted), or
   `rm -rf ~/.claude/plugins/cache/` (broader fallback). Exit the current session and start a new one.
2. **Cursor:** run `bash /path/to/lore-framework/scripts/cursor-refresh-plugin`, then start a fresh
   `cursor-agent --plugin-dir /path/to/lore-framework` session.
3. **Codex:** `codex plugin marketplace upgrade lore-framework` (or `codex plugin add lr@lore-framework`),
   then start a fresh Codex session.

If you skip the refresh, the prior version's `session-takeover` script and `docs/takeover.md` can
remain loaded. See `docs/doctor-stale-plugin-cache.md` (Claude) or
`docs/doctor-cursor-session-without-plugin.md` (Cursor missing skills).

## Status

Stable on Claude Code. **BETA on Codex** and **BETA on Cursor** for the core lifecycle surface.
`/lr:takeover` is **BETA** on all engines.

## What's New

### Cursor takeover conversion (completes v24 promise)

- **`scripts/session-takeover`** — `parse_cursor()` reads ordered
  `~/.cursor/projects/.../agent-transcripts/<uuid>/<uuid>.jsonl` for message order; pairs tool
  results from the matching `~/.cursor/chats/.../store.db` using batch-window name matching
  (parallel calls may complete out of JSONL order).
- **Listing** — Cursor rows now show resolved title, model, status, and path to the JSONL transcript;
  timestamps display in the **local timezone**.
- **Resolution** — session UUID, JSONL path, or `store.db` path (redirects to sibling JSONL);
  ambiguous multi-match paths error explicitly.
- **`pairing_uncertain`** — set when tool-result counts differ, or when a batch contains parallel
  calls with the same tool name (name-only pairing within the window).
- **`[REDACTED]`** assistant text at rest is omitted from digests; the footer documents this.

### `docs/takeover.md`

- Engine table: Cursor convert column updated to **yes**.
- Procedure and See Also aligned with the shipped behavior.

## Known limitations (unchanged BETA caveats)

- Same-name parallel tool batches may pair results incorrectly even when counts match — digest flags
  `pairing_uncertain`.
- Cursor assistant prose stored as `[REDACTED]` cannot be recovered.
- IDE-only vs CLI transcript parity not separately verified (CLI-heavy validation: 364/364 local
  sessions on one machine).
