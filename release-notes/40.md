# Release Notes — Version 40

## Summary

Version 40 adds a compact **Learning** section to every canonical host session summary. It shows,
per active agent, what reflection considered worth retaining, how merge changed or simplified Lore,
and whether anything remained unmerged.

The section is deliberately lean and body-only. Lore remains the durable knowledge source; the
summary now provides a human-readable audit of the learning process that can support richer learning
reports later without introducing a new schema today.

**Migration required:** no. Existing summaries remain valid, and no agent-repository structure or
frontmatter changes are required.

## Clear Plugin Cache

This release changes SKILL-referenced finalization procedures, so refresh the installed plugin
before using it.

1. **Claude Code:** `rm -rf ~/.claude/plugins/cache/lore-framework/` (targeted; preserves other plugins' caches), or `rm -rf ~/.claude/plugins/cache/` (broader fallback).
2. **Cursor:** run `bash /path/to/lore-framework/scripts/cursor-refresh-plugin`.
3. **Codex:** run `bash /path/to/lore-framework/scripts/codex-refresh-plugin`.
4. Exit the current session and start a new one.

If you skip this step, the previous plugin's finalization procedure remains in effect. See
`docs/doctor-stale-plugin-cache.md` for diagnosis.

## What Changed

- `process-merge.md` now returns one compact handoff per agent: the durable themes selected from
  reflection, concrete Lore actions (including consolidation and simplification), residual unmerged
  reflections, and anomalies. Current-session reflection paths keep retried, carried-over topics
  from being misreported as learning from this session.
- `summarize.md` turns the retained reflection outcomes and merge handoffs into a mandatory
  `## Learning` section in the canonical host summary. Explicit empty, failed, and
  standalone-not-assessed states prevent missing evidence from looking like “nothing learned.”
- `finalize.md` retains every reflection outcome and merge handoff through summarization, rather
  than retaining merge returns only for guest-summary generation.
- Guest-summary shape and all summary frontmatter schemas are unchanged. Guest summaries already
  carry their short `## Lore updates` list and link back to the canonical host summary.
- The public README was refreshed after v39 to clarify Lore's anatomy and how agents learn; those
  content-only commits are included in the v40 release range.

## Validation

- **Deterministic suite green:** 435 tests discovered, 387 run, and 48 real-engine lifecycle tests
  skipped because `LR_LIFECYCLE` was not enabled for the general suite.
- **One Codex finalization lifecycle scenario green:** `test_13_finalize_end_to_end` passed against
  the v40 candidate on `gpt-5.4` in 350.569 seconds. It verified that reflection's concrete canary,
  merge's Lore destination, and the merge outcome all reached the final `## Learning` section. An
  earlier run of the same scenario exposed category-only wording that dropped the canary; the
  procedure was tightened and the shipped tree is the successful rerun.
- **Focused post-change review:** three independent read-only reviews covered merge-to-summary data
  flow, empty/failure-state truthfulness, guest action normalization, engine-adapter alignment, and
  release claims. Their material findings were applied; a final verification of the phase-state
  and current-session attribution rules returned clean. This did not invoke the quality harness.
- **Not run:** the quality suite and Claude/Cursor real-engine lifecycle scenarios, by explicit user
  direction for this small release. The release therefore makes a real-engine execution claim only
  for the validated Codex path above.
